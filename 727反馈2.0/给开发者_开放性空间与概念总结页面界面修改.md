## 🎯 设计理念：认知地图式

### 核心概念

开放性空间不是"问题清单"或"待办任务"，而是**讨论地图**——让访谈者知道"有哪些可讨论的方向""从哪里开始""为什么要讨论这个"。

### 设计目标

| 从什么 | 到什么 |
|--------|--------|
| 展示所有问题（问题清单） | 讨论地图（引导方向） |
| 必须完成所有任务（待办清单） | 可以选择探索（访谈者有主导性） |
| 8个平等卡片（缺乏主次） | 中央焦点+周边觉察（有主有次） |

### 访谈场景分析

**访谈15题结束后发生了什么**：
- 访谈者和被访者一起看屏幕（不是访谈者单看）
- 不是"访谈者提问，被访者回答"，而是"一起讨论"
- 被访者刚刚做完15题，可能有点累，需要轻松的氛围

**访谈者的需求**：
- 从"提问-记录"模式切换到"讨论-探索"模式
- 需要知道："还有什么可讨论的？""从哪个开始？""为什么要讨论这个？"

### v3.3的空间化设计哲学

**访谈界面的三区结构**（作为参考）：
```
┌───────────────────────────┬─────────────────┐
│ 【中央焦点区】（60%）       │ 【右侧觉察带】   │
│ 当前题目 + 答案选择        │ 思维气泡         │
├───────────────────────────┴─────────────────┤
│ 【下方钻取区】（默认折叠）                    │
└──────────────────────────────────────────────┘
```

**设计原则**：
- 不争不抢，有主有次
- 一屏可达，不用滚动
- 访谈者是主动的，不是被信息轰炸

### 话题分类说明

**⚠️ 重要说明**：

**HTML原型中的分类是示例性质**：
- 原型中显示的四个分类（类型反思、概念理解、社会拓展、概念总结）仅供参考
- **不是最终分类**，不代表实际的话题分类
- 具体分类需要根据"开放性空间"和"概念总结"两个页面的实际内容确定

**分类来源**：
- 保留两个页面原有的分类（如"未来规划"等）
- 将两个页面的所有问题按照原有逻辑进行归类
- 可以适当调整分类名称，使其更清晰

**建议分类数量**：
- 建议分为**6个主题**（而不是4个）
- 右侧觉察区可以容纳更多主题，不会显得拥挤
- 6个主题可以更细致地覆盖讨论的不同维度

**主题卡片格式**：
```
┌─────────────────────────┐
│ [图标] 主题名称          │
│ ─────────────────      │
│ 一行小字说明：           │
│ "该主题聚焦的问题，     │
│  以及与AI素养调研       │
│  主题的关系"            │
└─────────────────────────┘
```

**左侧焦点区问题来源**：
- 从"开放性空间"和"概念总结"两个页面迁移现有问题
- 不删除、不修改问题内容，只按分类重新组织
- 每个主题显示2-4个具体问题（根据该主题的问题数量）

## 📋 分类整理要求

### ⚠️ 原型分类与实际分类的区别

**重要说明**：
- HTML原型中显示的4个分类（类型反思、概念理解、社会拓展、概念总结）**仅供参考**
- **不是最终分类**，不代表实际的话题分类
- 原型的目的是展示界面布局和交互方式，不是确定具体分类

### 实际分类来源

**需要合并的两个页面**：
1. **开放性空间页面**（访谈15题结束后的开放讨论）
2. **概念总结页面**（概念总结相关的问题）

**分类原则**：
- 保留两个页面原有的分类（如"未来规划"等）
- 将两个页面的所有问题按照原有逻辑进行归类
- 可以适当调整分类名称，使其更清晰
- 删除重复的"追问"文字（如果有的话）

### 建议分类结构

**建议分类数量**：6个主题

**每个主题的结构**：

| 字段 | 说明 | 示例 |
|------|------|------|
| 主题名称 | 从两个页面原有的分类中提取 | "未来规划"、"使用体验"、"概念理解" |
| 图标 | 可选，用于视觉识别 | 🖊️、📖、⭐、📝、🔮、💡 |
| 一行说明文字 | **必需**，说明该主题聚焦的问题及与AI素养调研的关系 | "从个人AI使用经验出发，反思个人与AI的关系" |
| 具体问题 | 从两个页面迁移，2-4个问题 | "你通常在什么情况下使用AI？" |

**一行说明文字的写法**：

❌ 不好的写法：
- "这个主题很重要"
- "讨论相关问题"
- "深入思考"

✅ 好的写法：
- "从个人AI使用经验出发，反思个人与AI的关系"
- "探索'AI素养'对你意味着什么，以及如何定义"
- "从个人体验延伸到社会层面的影响和思考"

### 分类整理步骤

**步骤1：收集所有问题**
- 列出"开放性空间"页面的所有问题
- 列出"概念总结"页面的所有问题

**步骤2：确定分类**
- 基于两个页面原有的分类
- 保留有意义的分类名称（如"未来规划"）
- 调整不清晰的分类名称
- 确保分类数量在6个左右

**步骤3：编写说明文字**
- 为每个分类编写一行说明文字
- 说明该分类聚焦的问题
- 说明与AI素养调研主题的关系

**步骤4：分配问题**
- 将问题分配到对应的分类
- 每个分类2-4个问题
- 不删除、不修改问题内容

### 默认状态

**页面加载时**：
- 默认选中第一个话题（类型反思）作为焦点
- 焦点区显示该话题的具体问题
- 觉察区显示所有话题的导航卡片，当前选中的高亮显示
- 对话记录区显示空白输入框

### 点击交互

**点击觉察区的话题卡片**：
1. 移除所有卡片的 `active` 状态
2. 为点击的卡片添加 `active` 状态
3. 更新焦点区的内容为该话题的：
   - 标题
   - 图标
   - 维度标签
   - 具体问题列表

**JavaScript示例**：
```javascript
// 点击话题卡片切换焦点
function switchTopic(topicId) {
  // 1. 更新导航卡片的active状态
  document.querySelectorAll('.nav-card').forEach(card => {
    card.classList.remove('active');
  });
  document.querySelector(`[data-topic="${topicId}"]`).classList.add('active');

  // 2. 更新焦点区的内容
  const topic = topics[topicId];
  document.querySelector('.focus-title').textContent = topic.title;
  document.querySelector('.focus-icon').textContent = topic.icon;
  document.querySelector('.focus-dimension').textContent = topic.dimension;

  // 3. 更新问题列表
  const questionsHtml = topic.questions.map(q =>
    `<div class="question-item"><p class="question-text">${q}</p></div>`
  ).join('');
  document.querySelector('.focus-content').innerHTML = questionsHtml;
}
```

### 问题点击交互

**点击焦点区的问题卡片**：
- 在对话记录区添加该问题的标题（方便访谈者记录）

**可选功能**：
- 点击问题卡片 → 展开输入框
- 访谈者可以记录被访者的回答要点

## 💬 补充说明

### 页面合并说明

**概念总结页面的处理**：
- 概念总结页面的问题不再单独作为一页
- 所有概念总结问题融入到开放性空间的四个话题中
- 具体分配方式：
  - "类型反思"话题：融入自我反思相关问题
  - "概念理解"话题：融入概念定义相关问题
  - "社会拓展"话题：融入社会影响相关问题
  - "概念总结"话题：保留原有的总结性问题

**用户可见性**：
- 访谈者和被访者都可以看到这个页面
- 这是"一起讨论"的空间，不是"测试"
- 对话记录区只对访谈者可见

### 与访谈界面的设计一致性

开放性空间采用与访谈界面相同的设计哲学：
- **空间化布局**：中央焦点 + 周边觉察 + 深度钻取
- **一屏可达**：不用滚动，眼睛扫一下就能看到需要的信息
- **不争不抢，有主有次**：焦点区权重高，觉察区权重低
- **访谈者有主导性**：可以选择话题，而不是被信息轰炸
