## 新设计的核心逻辑

### 1. 唯一正确的类型划分：3维度极性制

**只有3个维度对，不再有8种人格类型**：

| 维度对 | 两端 | 判定逻辑 |
|-------|------|---------|
| **维度1：探索者-实用者** | 探索者(E) vs 实用者(U) | E分数 > U分数 → 偏向E<br>U分数 > E分数 → 偏向U |
| **维度2：信任者-验证者** | 信任者(T) vs 验证者(V) | T分数 > V分数 → 偏向T<br>V分数 > T分数 → 偏向V |
| **维度3：功能者-反思者** | 功能者(F) vs 反思者(R) | F分数 > R分数 → 偏向F<br>R分数 > F分数 → 偏向R |

**类型代码示例**：
- E+T+F = ETF（不是"AI反思者"！）
- U+V+R = UVR（不是"AI观察者"！）

### 2. 网络梗+动物形象（仅作标签）

**仅用于生动命名，不暗示优劣**：

| 类型代码 | 网络梗名 | 动物形象 | 说明 |
|---------|---------|---------|------|
| **ETF** | 摸鱼人 | 好奇猫 | E+T+F组合，仅作标签 |
| **ERF** | 质疑党 | 谨慎狗 | E+V+F组合，仅作标签 |
| **UTF** | 工具人 | 忙碌蜂 | U+T+F组合，仅作标签 |
| **UVF** | 保守派 | 稳妥龟 | U+V+F组合，仅作标签 |
| **ETR** | 哲学家 | 智慧猫头鹰 | E+T+R组合，仅作标签 |
| **ERR** | 批判家 | 批判狐狸 | E+V+R组合，仅作标签 |
| **UTR** | 实干家 | 实践大象 | U+T+R组合，仅作标签 |
| **UVR** | 老古董 | 守仓松鼠 | U+V+R组合，仅作标签 |

**重点**：
- ✅ 这些是**类型代码标签**（如ETF），不是独立的人格类型
- ✅ 仅用于生动命名（如"摸鱼人"）
- ✅ **不暗示优劣**（如"哲学家"不代表"比工具人高级"）

### 3. 对比条形图（MBTI风格）

**唯一正确的可视化方式**：

```
┌─────────────────────────────────────────────────────────────────┐
│  🎭 你的类型：AI摸鱼人（好奇猫型）                               │
│                                                                 │

│     vs                                                          │

│     vs                                                          │
│     验证者 71%  ─────────● 5.0/7                                │
│     你偏向【信任者】端，倾向强度 7%                              │
```

**关键元素**：
- ✅ 3对维度对比（E vs U、T vs V、F vs R）

- ✅ **无优劣暗示**（只说"倾向强度"，不说"能力强弱"）

```python
# 正确的3维度极性计算
def calculate_dimension_polarity(exploration_score, utilizer_score,
                               truster_score, verifier_score,
                               functionalist_score, reflector_score):
    """
    计算3维度极性（E-U, T-V, F-R）
    """
    # 维度1：探索者-实用者
    eu_position = "E" if exploration_score > utilizer_score else "U"
    eu_bias = ((exploration_score - utilizer_score) / 7) * 100

    # 维度2：信任者-验证者
    tv_position = "T" if truster_score > verifier_score else "V"
    tv_bias = ((truster_score - verifier_score) / 7) * 100

    # 维度3：功能者-反思者
    fr_position = "F" if functionalist_score > reflector_score else "R"
    fr_bias = ((functionalist_score - reflector_score) / 7) * 100

    # 组合类型代码
    type_code = eu_position + tv_position + fr_position  # 如"ETF"

    return {
        "type_code": type_code,
        "dimensions": [
            {
                "name": "探索者-实用者",
                "position": eu_position,
                "bias": eu_bias,
                "exploration_percent": round((exploration_score / 7) * 100, 0),
                "utilizer_percent": round((utilizer_score / 7) * 100, 0)
            },
            # ... T-V, F-R
        ]
    }
```

## 常见问题（FAQ）

### Q1: 为什么删除"AI反思者"这个名称？

**A**: "AI反思者"是v2版本的旧分类，暗示"反思能力强=好"。v3版本采用3维度极性制，不暗示优劣。正确的类型代码是ETF/ERF/UTF等，不使用"AI反思者"这样的名称。

### Q2: 用户问"我是哪种类型？"如何回答？

**A**: 回答"你的类型代码是ETF（摸鱼人/好奇猫型），偏向探索者-信任者-功能者端"。重点说明3个维度的倾向，而不是给出一个笼统的"类型名称"。

### Q3: 百分比90%是否意味着"能力很强"？

**A**: 不是！90%仅表示"倾向强度"，即"你的行为模式90%符合探索者特征"。这不代表"探索能力强=好"，只是说明你的协作风格偏向探索者端。

### Q4: 为什么不保留"优势/劣势"说明？

**A**: 因为"优势/劣势"暗示优劣，违背"无优劣"原则。每种协作风格都值得研究，没有哪种"更好"。

### Q5: 网络梗名称（如"摸鱼人"）是否暗示优劣？

**A**: 不会！"摸鱼人"、"哲学家"等名称仅用于生动性，不暗示优劣。"哲学家"不代表"比工具人高级"。
