**文档版本**: v1.0

**项目阶段**: 产品定位重构与交互逻辑重新设计
**核心问题**: 访谈引擎的产品定位还没有完全落实到交互逻辑中

---

## 🎯 核心问题诊断

### 当前版本的隐含假设（错误）

> AI知道应该问什么，所以把问题生成出来提供给访谈者。

### 正确的产品定位

> AI不知道现场应该问什么，但它能够帮助访谈者保持分析视角、提醒关键维度、激活可能遗漏的方向。

### 产品定位的转变

**从**: AI访谈员（替访谈者提问）
**到**: 增强型访谈辅助系统（AI-augmented interviewer）

**不是**: 降低访谈难度或替代人类提问
**而是**: 扩大访谈者的观察能力和理解深度

## 🎯 议程1：产品定位重新确认（已跳过）

### 核心议题
从"AI访谈员"到"AI-augmented interviewer"的转变边界在哪里？

### 三个人机分工的关键点

#### 1.1 人类访谈者的不可替代能力

**情境判断**
- 被访者此刻的情绪
- 哪个故事值得继续追
- 哪个方向应该深入
- 什么时候应该转换话题

**关系建立**
- 倾听
- 共情
- 临场调整
- 根据回答产生新的问题

**界面设计原则**: 这些能力在界面设计上应该如何"留白"？

#### 1.2 AI的三个核心价值

**保持研究框架**
- 提醒"这个回答涉及AI识别能力"

**提供认知扩展**
- "你还可以想到"而不是"你应该问"

**建立跨题关联**
- "Q1回答可能关联Q3使用、Q8信任"

**界面设计原则**: 这三个价值在界面上的呈现方式是什么？

#### 1.3 "增强型访谈辅助系统"的精确定义

- 不是替代人类提问
- 不是降低访谈难度
- 而是扩大访谈者的观察能力和理解深度

**界面设计原则**: 如何界定"扩大观察"与"干扰访谈"的边界？

## 🎯 议程2：交互结构重构（实施中）

### 从"三步流程"到"四个思考窗口"

#### 2.1 一个核心问题 + 四个思考窗口的结构

```
┌─────────────────────────────────────────┐
│ 【核心问题区】                            │
│ Q1: 我通常能够判断...                    │
│                                          │
│ 【思考窗口1：题目理解 Meaning】           │
│ 这个问题在问什么？                       │
│ 关键词：识别 · 分辨 · 判断               │
│                                          │
│ 【思考窗口2：经验叙事 Experience】        │
│ 故事入口：第一次接触 / 典型经历 / 变化   │
│                                          │
│ 【思考窗口3：选择解释 Choice】            │
│ 为什么5分？为什么不是6分？               │
│                                          │
│ 【思考窗口4：素养关联 Literacy】          │
│ 研究关联：AI识别能力 → AI理解 → 技术判断 │
└─────────────────────────────────────────┘
```

#### 2.2 四个思考窗口的内容设计

**窗口1（题目理解 Meaning）**

```
这个问题在问什么？

关键词：识别 · 分辨 · 判断

可以关注：
- TA如何理解"AI"
- TA认为什么算"真正使用AI"
- TA有没有质疑题目
```

**关键设计问题**：
- "关键词"是预定义的，还是动态提取的？
- "可以关注"是指导性的，还是启发性的？

**窗口2（经验叙事 Experience）**

```
可能的故事入口：

第一次：
- 第一次听说AI是什么时候？
- 第一次觉得AI和自己有关？

典型经历：
- 有没有一次经历改变了你对AI的看法？

变化：
- 对AI的认识有没有变化？
```

**关键设计问题**：
- 这些入口是穷尽列举，还是示例性质？
- 是否需要"优先级"排序？

**窗口3（选择解释 Choice）**

```
你的选择：5分（比较同意）

可能意味着：
- 能够识别AI应用
- 对AI有一定判断标准

探索方向：
这种判断来自哪里？
```

**关键设计问题**：
- "可能意味着"是否暗示了价值判断？
- "探索方向"是否应该更开放？

**窗口4（素养关联 Literacy）**

```
研究关联：

本题涉及：
AI识别能力
↓
AI理解能力
↓
技术判断能力

注意区分：
描述知识 vs 描述经验判断
```

**关键设计问题**：
- 这个层级关系（→）是固定框架，还是可调整的？
- "注意区分"是否应该更具体？

## 🎯 议程3：界面原型设计（实施中）

### 从"问题卡片"到"认知地图"

#### 3.1 中央极简区

```
┌─────────────────────────────────────────┐
│  阶段1: 初识 | Q1/3                     │
│  ─────────────────────────────────────  │
│                                          │
│  Q1: 我通常能够判断，一个应用或服务是否  │
│      真正使用了AI                        │
│                                          │
│  关键词：识别 · 分辨 · 判断 ◇            │
│  ─────────────────────────────────────  │
│                                          │
│  你的答案：[1-7选择器]                   │
│  被访者回答：[输入框]                    │
└─────────────────────────────────────────┘
```

**关键设计问题**：
- "关键词"显示在题目下方，还是右侧？
- "◇"符号是装饰性的，还是有交互功能？

#### 3.2 右侧思维气泡（动态展开）

```
┌─────────────────────────────────────────┐
│  💭 想想（3）                            │
│  ─────────────────────────────────────  │
│                                          │
│  ⏱️ 14:28  这个人如何理解"AI"？         │
│                                          │
│  ⏱️ 14:25  他的判断依据是什么？          │
│                                          │
│  ⏱️ 14:20  他有没有经历过误判？          │
│                                          │
│  ─────────────────────────────────────  │
│  [点击查看更多 →]                       │
│                                          │
│  ─────────────────────────────────────  │
│  [+ 添加想法]（按回车发送）              │
└─────────────────────────────────────────┘
```

**关键设计问题**：
- "想想"中的问题是预定义的，还是实时生成的？
- 是否需要"优先级"排序？
- 是否需要"分类标签"？

#### 3.3 下方三模块区

```
┌─────────────────────────────────────────┐
│  【故事入口】                            │
│  第一次接触AI / 典型经历 / 变化节点     │
│                                          │
│  【选择解释】                            │
│  为什么5分？为什么不是6分？              │
│                                          │
│  【研究关联】                            │
│  AI识别能力 → AI理解 → 技术判断         │
└─────────────────────────────────────────┘
```

**关键设计问题**：
- 三个模块是横向排列，还是垂直堆叠？
- 每个模块是否需要"折叠/展开"功能？
- 是否需要"优先级"排序？

## 🎯 议程5：AI生成逻辑设计（实施中）

### 离线生成 + 人工审核

#### 5.1 生成流程

```
Step 1: 人工定义Question Schema框架
↓
Step 2: AI生成四个思考窗口的内容
↓
Step 3: 人工审核和调整
↓
Step 4: 存入数据库
↓
Step 5: 访谈时按需调用
```

**关键设计问题**：
- Step 2的AI生成需要什么Prompt？
- 人工审核的标准是什么？
- 是否需要"版本管理"？

#### 5.2 AI生成Prompt设计

**Prompt模板**：

```
你是一个质性研究专家，正在为一道AI素养访谈题设计访谈辅助内容。

题目内容：{question_content}

核心能力：{core_literacy}
关键词：{keywords}

请生成以下内容：

1. 【题目理解】
- 这道题在问什么？
- 访谈时可以关注哪些方面？

2. 【经验叙事】
- 提供可能的故事入口（第一次、典型经历、变化）
- 每个入口提供1-2个示例问题

3. 【选择解释】
- 对于Likert 1-7分，每个分数段可能意味着什么？
- 哪些探索方向值得关注？

4. 【素养关联】
- 这道题涉及哪些AI素养维度？
- 访谈时需要注意区分什么？

要求：
- 语言要口语化，不要学术术语
- 不要提供固定问题，而是提供思路方向
- 保持开放性，不要暗示"正确答案"
- 强调"每种回答都值得理解"
```

**关键设计问题**：
- 这个Prompt是否足够清晰？
- 是否需要"示例"（few-shot learning）？
- 如何保证AI生成的内容符合"去价值化"原则？

#### 5.3 跨题关联的生成逻辑

**方法1：基于规则**
```
IF 被访者提到"使用" OR "工具" OR "ChatGPT"
THEN 提示可能关联Q3（使用习惯）
```

**方法2：基于语义**
```
将被访者回答进行向量化
与Q3、Q7、Q10的主题向量进行相似度计算
如果相似度 > 0.7，提示关联
```

**关键设计问题**：
- 哪种方法更适合10天MVP？
- 跨题关联的呈现时机是什么？

## 🎯 议程7：验收标准（已跳过）

### 如何判断"增强型访谈辅助系统"是否成功？

#### 7.1 功能验收

- [ ] 访谈者能够看到四个思考窗口（不是三步流程）
- [ ] 思维气泡能够记录灵感并动态展开
- [ ] 跨题关联能够在适当时候提醒访谈者

#### 7.2 体验验收

- [ ] 访谈者不觉得界面信息过多
- [ ] 访谈者能够自主掌控访谈节奏
- [ ] 访谈者觉得AI"扩大了观察"，而不是"干扰了访谈"

#### 7.3 研究价值验收

- [ ] 访谈记录能够体现"并列关系"（15题独立）
- [ ] 访谈记录能够体现"历时关系"（4阶段叙事）
- [ ] 被访者能够进行开放性空间的反思（15题后）

## 🎯 核心设计原则总结

### 1. 人机分工原则

**人类访谈者负责**：
- 情境判断
- 关系建立
- 临场调整

**AI负责**：
- 保持研究框架
- 提供认知扩展
- 建立跨题关联

### 2. 界面设计原则

**不是**：
- 减少信息（极简主义）
- 告诉访谈者"该问什么"

**而是**：
- 更好的信息组织（认知地图）
- 帮助访谈者"看到更多可能性"

### 3. 内容生成原则

**不是**：
- 实时生成访谈问题
- 替代人类思考

**而是**：
- 离线生成 + 人工审核
- 提供思考维度和方向

### 4. 访谈流程原则

**不是**：
- 线性流程（故事→经历→反思）

**而是**：
- 四个思考窗口（并列呈现，访谈者自主选择）
