## 3. 规划沿革的重建

### 3.1 思想起点

根目录的技术路径总纲把 ALIS 定义为社会学研究软件，而不只是问卷页面。最初的思想组合是：

1. 用量表把 AI 素养拆成可追踪的能力/实践/经验/情境/倾向陈述。
2. 用确定性的评分和类型化结果形成可解释的“测量—测试—成员分类”链路。
3. 在测量之后进入访谈，让追问暴露被试如何理解自己、如何叙述经验以及何时修正判断。
4. 把促进者的现场经验、访谈事件、反应和研究导出纳入同一 session timeline。

总纲明确区分了两个叠加产品：一条较早可交付的 MBTI-like 评估路径，以及次年继续发展的 Interview OS。八个月边界并不是一次性完成完整访谈操作系统，而是先实现前三层和一个单题追问片段。这一边界有助于解释为什么代码同时出现“类型码/剖面”和“六阶段访谈”两套产品语言。

### 3.2 S0-S6 工程路径

## 4. 当前代码架构

### 4.1 总体数据流

```text
内容 YAML（量表/维度/追问树/类型轴）
              │
              ├── 前端离线解析与校验 ──> 简单模式：7 点 → 风格分类 → 六阶段访谈
              │                                      │
              └── 后端 pack 校验 ──> 详细模式：6 点 → XState → 维度剖面 → 单题追问
                                                     │
                                      FastAPI 认证/保存/导出/研究时间线
                                                     │
                                  SQLite（默认）/PostgreSQL（规划）
```

### 4.2 前端

前端是 React 18 + TypeScript + Vite + XState 5 + Vitest。关键模块如下：

| 模块 | 职责 |
| --- | --- |
| `src/App.tsx` | 登录、会话恢复、模式选择、简单/详细流程编排、访谈保存与完成报告 |
| `src/content/bundledPack.ts` | 从后端 YAML 导入并在浏览器端校验内容包 |
| `src/domain/pack.ts` | 内容包 schema、15 题/7 维预期、评分配置推导 |
| `src/domain/scoring.ts` | 反向计分、题目均值和维度均值的纯函数 |
| `src/domain/norms.ts` | midpoint 临时常模、0–100 映射和置信区间估计 |
| `src/domain/deviation.ts` | 维度残差/偏差题选择；按内容包顺序处理并列 |
| `src/domain/typecode.ts` | 4 轴、50 百分位切分、置信区间跨中位数时小写不确定码 |
| `src/domain/styleClassifier.ts` | 简单模式的 E-U、T-V、F-R 三轴与 8 类风格分类 |
| `src/machine/evaluationMachine.ts` | 详细模式 `eliciting → locked → scoring → profiling → selectingProbe → done` |
| `src/offline/commitQueue.ts` | IndexedDB 提交队列；成功删除，失败保留，顺序刷新 |
| `src/utils/persistDraft.ts` | 访谈草稿先写本地、按时间顺序 flush，失败不丢 |
| `public/sw.js` | shell 缓存、导航 network-first、静态资源 cache-first；非 GET 不拦截 |

简单模式不是详细模式的别名：`onSimpleLock()` 直接调用 `classifyStyleV3(simpleResponses)`，并进入自己的访谈 UI。详细模式才把回答送入 `evaluationMachine` 并生成 `ProbeTarget`。`App.tsx` 中的桥接 TODO 和 `showDetailAvailable={false}` 说明统一入口当时还没有完成。

### 4.3 后端

后端是 FastAPI 应用工厂，主要层次为：

- `api.py`：路由、依赖注入、认证、CSRF Origin/Referer 检查、owner 权限、限流、事务边界和静态前端挂载。
- `content.py`：YAML 内容加载，严格校验 15 题、7 维和追问树字段。
- `models.py`：当前包含 Session、LikertResponse、DimensionScore、PersonalityProfile、ProbeEvent、NarrativeSegment、QuestionReaction、User、AuthSession、InterviewRecord 等模型类；旧注释仍说“7 张初始表”，属于文档漂移。
- `db.py`：默认 SQLite，启用 WAL、外键和 busy timeout；可通过环境变量转 PostgreSQL。
- `probe.py`：`LLMClient` 协议、Stub 客户端、懒加载 LiteLLM 客户端；模型默认 `deepseek/deepseek-chat`，异常或坏输出回退为骨架问题。
- `transcribe.py`：本地 faster-whisper 的可选协议和 Stub；设计注释要求不把音频上传云端，并设置短期删除边界。
- `bundle.py` / `export.py`：JSON、CSV、ZIP bundle、manifest 和 SHA-256 校验。

当前 API 覆盖健康检查、登录/登出/当前用户、会话开始、追问渲染、矛盾追问、会话提交、历史会话、统计、宽/长表导出、bundle 导出、叙事注册、访谈保存和访谈快照。会话提交由服务端内容包决定有效量表；当前优先接受 `likert_simple` 的 1–7 路径。

### 4.4 数据与隐私

数据结构遵循“统一时间线 + session bundle”的思路：量表回答、维度得分、画像、追问事件、访谈段落、问题反应和审阅信息能被关联。音频模型保存的是 `audio_file_id` 指针，而不是把音频字节直接塞进数据库；bundle 导出在源路径存在时仍可能复制音频文件，因此“设计上的不入库”与“导出时复制文件”之间需要在正式使用前再做一次隐私核验。

认证使用 Argon2、HttpOnly/SameSite cookie、用户名/IP 限流和 owner 检查；年龄筛查未通过时由服务端拒绝开始会话。这里的代码级安全措施不等于生产环境合规认证，正式部署还需重新检查 CORS、密钥、日志、备份、HTTPS 和管理员账户。

## 5. 算法和状态机复盘

### 5.1 详细评分链

详细路径的设计遵守“逻辑不交给 LLM”：

1. 题目 raw 值进入纯函数；反向题使用 `min + max - raw`。
2. 每个维度计算题目有效值的均值。
3. midpoint 临时常模把维度均值映射到 0–100；题数足够时给出均值 ± 1.96×SE 的区间。
4. 四条类型轴从 D4、D2、D5、D7 读取百分位；50 为切分点，置信区间跨点时以小写表示未分化。
5. 维度偏差默认使用“维度残差”策略，按最大残差选目标；并列按内容包顺序解决。
6. XState 锁定全部 15 题后冻结回答，进入评分、剖面、追问选择和完成态；停止后的 actor 不应继续接受事件。

### 5.2 简单模式链

简单模式使用 YAML 中的 `likert_simple`：1–7 点，含中立/不确定锚点。`styleClassifier.ts` 复用题目回答形成三组轴，并输出 8 类 `typeCode`、类型定义、维度摘要、置信度和反思题。它在产品体验上更适合作为面向被试的引导式入口，但它不等于 7 维连续评估。当前 YAML 是 `2.2-draft`，7 维分别覆盖识别、使用、学习与问题解决、理解、伦理与社会、人与 AI 关系、反思。

### 5.3 LLM 追问链

后端 `probe.py` 让模型看到结构化 `ProbeTarget`、题干、维度、量表方向、类型和追问骨架，系统提示强调“只生成一句自然问题，不改变评分或分支”。返回空字符串、超过 300 字或调用异常时使用 skeleton fallback，并把 `fallback` 标记写入事件。这样模型的生成质量会影响语言体验和可解释性，但不应改变目标题、维度或研究编码。
