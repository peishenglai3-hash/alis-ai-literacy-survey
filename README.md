> 本仓库是 ALIS 项目的只读重建基线与私有托管版本。审计于 2026-09-09 完成；本次没有修改既有业务源码、成品或外部反馈原文。GitHub private 远程已创建，`main` 与本地基线 SHA 已回读一致。

## 项目是什么

ALIS（AI Literacy Interview Survey）是一个社会学取向的 AI 素养情境化访谈系统。它把量表测量、解释性画像、单题追问、促进者访谈记录和研究导出放在同一条可追溯链路中，目标不是让模型替代评分或研究判断，而是让 AI 参与语言生成，同时保留规则、状态和研究者的可检验性。

当前代码保留了两条历史上并存的产品路径：

- 默认“简单模式”：7 点量表，使用 3 组风格轴生成 8 类结果，再进入 6 阶段访谈与复盘报告。
- “详细模式”：6 点量表，按 7 个维度计算连续剖面，通过 XState 状态机选择一个偏差题并调用后端语言生成追问。

两条路径共用内容包、认证、保存、导出和部分研究数据结构，但目前并非同一个评分入口。`frontend/src/App.tsx` 中仍保留了把简单模式接入详细状态机的 TODO；这被记录为现状边界，不在本次任务中擅自修复。

## 本地运行

后端（建议使用项目既有虚拟环境或等价 Python 环境）：

```powershell
cd alis-mvp/backend
python -m pytest -q
```

前端：

```powershell
cd alis-mvp/frontend
npm install
npm run typecheck
npm test -- --run
npm run build
```

运行服务前请从 `.env.example` 复制环境文件并自行填入密钥；真实 `.env`、SQLite 数据库、音频、导出包和部署凭据不应提交。后端默认使用本地 SQLite，生产数据库、模型和 CORS/认证配置应按部署环境单独核验。

## 重要设计约束

1. LLM 负责语言，不负责评分、分支或研究分类；评分与状态机应保持确定性。
2. 研究数据、音频和导出包应按最小化原则处理；原始交互档案不作为公开仓库内容。
3. 反馈文件是设计证据，不是可以直接执行的补丁清单。先复述目标、确认范围，再决定局部修补或重写。
4. 现有实现的历史漂移必须被记录后再决策，尤其是简单/详细模式、7 点/6 点量表和旧版 README 的不一致。
