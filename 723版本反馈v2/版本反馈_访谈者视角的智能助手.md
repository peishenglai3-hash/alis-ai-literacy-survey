**反馈版本**: 当前MVP迭代版
**反馈日期**: 2026-07-23
**核心定位调整**: 访谈引擎是访谈者的智能助手，不向被访者展示

## 一、关键使用场景澄清（🔴重要！）

### 田野使用方式

```
┌─────────────────────────────────────────────────────────────┐
│                                                              │
│   访谈者（大二学生）         访谈引擎界面        被访者       │
│      👁️                        💻                           │
│   ┌─────────┐              ┌─────────┐         👤          │
│   │主导访谈 │◄─────────────►│故事引导 │◄────────┐         │
│   │决定方向 │              │提供线索  │          │         │
│   │深度对话 │              │不实时生成│          │         │
│   └─────────┘              └─────────┘          │         │
│         ▲                                        │         │
│         │  (不直接交互)                          │         │
│         └────────────────────────────────────────┘         │
│                    (深度对话)                               │
│                                                              │
└─────────────────────────────────────────────────────────────┘

访谈者 ↔ 引擎：访谈者查看引擎提示，选择性使用，不实时交互
访谈者 ↔ 被访者：访谈者主导节奏和方向，进行深度访谈
引擎 ↔ 被访者：不直接交互，引擎基于测试答案生成静态引导内容
```

### 🔴 关键限制与能力边界

**AI引擎的限制**：
- ❌ **不进行实时性的智能化访谈提问生成**
- ❌ **不根据被访者的现场反馈调整追问**
- ❌ **不主导访谈节奏和方向**

**AI引擎的能力**：
- ✅ 根据测试答案生成人物画像（人格类型判定）
- ✅ 提供6个板块的结构化引导（认识→使用→信任→相处→理解→重新定义）
- ✅ 对每道题提供**故事化引导**（非模板化提问）
- ✅ 结合人格类型，提供类型视角的追问线索

**人类访谈者的主导角色**：
- ✅ **掌握访谈节奏和方向**（问什么、什么时候问、怎么问）
- ✅ **根据每道题回答进行针对性提问**（用自己的语言，结合现场氛围）
- ✅ **判断引擎建议的价值**（使用、忽略、调整）
- ✅ **建立访谈关系**（共情、倾听、追问）

**核心含义**：
- ✅ 访谈者是"主导者"，不是被动的执行者
- ✅ 引擎是"故事引导库"，不是"实时对话系统"
- ✅ 引擎界面是**参考工具**，不是**访谈脚本**
- ✅ 引擎提供"由浅入深"的叙事线索，符合社会学质性访谈结构

## 二、当前版本的核心问题

### 问题1：追问建议过于模板化，缺乏故事化引导

**现状**：
```
阶段1：认识AI
追问建议：
- Q1：如何判断AI？
- Q1：想到了什么具体内容和事件？
- Q1：为什么做这个选择？
- Q1：有什么困惑的？
```

**问题诊断**：
- ❌ 问题像"考试题"或"问卷核对"，不像"访谈引导语"
- ❌ **过于模板化**，放之四海而皆准，缺乏针对性
- ❌ 缺乏"激发被访者讲故事"的叙事性
- ❌ 访谈者无法理解"为什么要问这个问题"

**访谈者视角的困惑**：
> "引擎给的建议都是套话，什么'如何理解、想到了什么、为什么选择'。
> 这种问题太生硬，我怎么把它转化为自然的对话？
> 我需要的是能帮助被访者打开话匣子的故事线索，而不是检查问卷。"

**❌ 避免：模板化提问**
```
"如何理解这道题？"           → 被访者不知道从何说起
"想到了什么具体内容和事件？" → 像老师检查作业
"为什么做这个选择？"         → 被访者已经忘记当时的思考
"有什么困惑的？"             → 可能没有困惑，问题失效
```

**✅ 期望：故事化引导**
```
"你什么时候第一次听说AI？"
→ 被访者回忆起具体时间点，故事开始

"从'知道AI'到'使用AI'的转折点是什么？"
→ 被访者讲述关键契机，叙事有了情节

"一开始使用AI时，你对它的态度是什么？"
→ 被访者回顾当时的期待、怀疑、好奇
```

**修正方案：AI提供"故事化引导"，人类进行"深度对话"**

AI引擎应该提供**分层递进的叙事引导**，而非单一的模板化问题：

```json
{
  "stage_id": 1,
  "stage_name": "认识AI",
  "current_focus": "Q1: 我能够清楚地分辨一个应用是否真正使用了AI",
  "user_answer": 6,
  "answer_meaning": "受访者在日常生活中能够清晰判断AI应用",

  "story_guidance": {
    "narrative_start": {
      "level": "浅层激发（回忆时间线）",
      "guidance": "你什么时候开始注意到AI的存在？是某个具体的产品、新闻，还是别人的推荐？",
      "why_works": "从具体时间点切入，帮助被访者追溯AI认知的形成起点"
    },

    "deepening_direction": {
      "level": "中层深化（关键场景）",
      "guidance": "第一次意识到'这个应用用了AI'时的情景是什么？那个瞬间让你对AI有了什么具体的印象？",
      "why_works": "引导被访者回忆具体场景，AI认知从抽象到具象"
    },

    "reflective_extension": {
      "level": "深层反思（从经验到理解）",
      "guidance": "现在回看，你当时对AI的判断准确吗？有什么新的理解？",
      "why_works": "从过去的故事转向当下的反思，形成认知闭环"
    }
  },

  "type_perspective": {
    "user_type": "AI探索者",
    "connection": "Q1高分符合该类型特征：倾向于主动识别和探索AI应用",
    "perspective_guidance": "从'AI探索者'的角度看，你对AI的识别有经验。这种'敏感度'从哪里来？是天生的好奇心，还是后天的培养？",
    "why_works": "从类型框架切入，提供第二视角，帮助访谈者探索被访者认知模式的形成原因"
  }
}
```

**访谈者使用场景**：
```
1. 访谈者看到："Q1(6)，受访者选了非常同意"
2. 访谈者转向被访者："Q1你选了'非常同意'，还记得当时怎么考虑的吗？"
3. 被访者："哦对，我觉得我能分辨..."
4. 访谈者快速扫视"AI故事化引导"
5. 访谈者选择"叙事起点"的角度（用自己的语言）："说到识别AI，你什么时候开始注意到AI的存在？"
6. 被访者开始讲述故事："大概是ChatGPT出来的时候..."
7. 访谈者根据故事内容，决定是否深入到"关键场景"或"反思引导"
8. 访谈者在"访谈记录区"记录要点
```

### 问题2：AI生成内容缺乏"为什么用这个引导"的解释

**现状**：
```
阶段1：认识AI
AI生成内容：
Q1(6) - 如何判断AI？
Q1(6) - 想到了什么具体事件？
```

**问题诊断**：
- ❌ 访谈者看到的是孤立的问题，不知道"为什么要这样引导"
- ❌ 缺乏"这个引导与原题答案的关系"的解释
- ❌ 缺乏"这个引导能帮我获得什么信息"的说明
- ❌ 访谈者难以判断"这个引导是否适合当前对话氛围"

**访谈者视角的困惑**：
> "引擎建议我问'什么时候第一次听说AI'，但我不知道：
> - 这个问题和Q1高分有什么关系？
> - 这个问题能帮我了解被访者的什么方面？
> - 如果被访者已经说了很多，还需要问这个问题吗？
> - 我应该用自己的语言问，还是照着念？"

**修正方案：AI生成内容必须包含三层信息**

**第一层：与原题答案的连接**
```
🔗 连接说明：
Q1(6)表示受访者能够清晰地分辨AI应用。
故事化引导从"能够分辨"出发，追溯这种能力的形成过程。
→ 目的：了解受访者的AI认知是如何形成的
```

**第二层：引导语言的工作原理**
```
💡 为什么这个引导有效：
"什么时候开始注意到AI的存在？" - 从时间点切入，帮助被访者回忆具体事件
→ 被访者容易回答（有明确的时间线）
→ 故事自然开始（从起点讲起）
→ 访谈者可以了解AI认知的形成背景
```

**第三层：预期访谈收获**
```
🎯 这个引导能帮你获得：
- 受访者第一次接触AI的时间点
- 是什么产品/事件触发了对AI的注意
- 受访者当时对AI的初始印象
→ 这些信息帮助理解受访者的AI认知起点
```

### 问题3：提问没有回到原题，被访者难以回忆当时的思考

**现状**：
```
阶段1：认识AI
AI生成：能分享一个识别AI的例子吗？
```

**问题诊断**：
- ❌ 被访者可能已经忘记Q1问的是什么
- ❌ 被访者可能忘记自己选了什么
- ❌ 缺乏"回忆当时的思考过程"的线索
- ❌ 追问与原题脱节，被访者不知道"为什么我们现在讨论这个"

**访谈者视角的困难**：
> "我想让被访者回忆Q1的思考过程，但界面没有显示原题和答案。
> 我需要一边翻看之前的记录，一边引导对话，很打断访谈节奏。"

**修正方案：界面必须"回到原题"，帮助被访者回忆**

访谈界面应该**始终显示**：
1. **原题内容**
2. **用户答案**（包括选择的含义）
3. **故事化引导**（基于原题答案生成）

**核心设计逻辑**：
```

### 问题4：6个板块之间缺乏过渡引导，叙事结构不连贯

**现状**：
```
阶段1：认识AI (完成)
阶段2：使用AI (进行中)
[没有过渡提示，访谈者不知道如何自然转向]
```

**问题诊断**：
- ❌ 访谈者不知道如何从一个阶段自然过渡到下一个阶段
- ❌ 缺乏"当前讨论什么"、"可以转向什么"的指引
- ❌ 6个阶段的**叙事逻辑**（认识→使用→信任→相处→理解→重新定义）没有体现
- ❌ 访谈容易变成"一题一题核对"，而非"连贯的故事旅程"

**访谈者视角的困难**：
> "Q1和Q2讨论完了，我想转到'使用AI'，但不知道怎么自然过渡。
> 直接说'现在我们聊聊使用AI'太生硬了。
> 我需要一些过渡语，帮助对话流畅地转向下一个话题。"

**修正方案：提供6阶段旅程地图+过渡建议**

**6个阶段的叙事逻辑**：
```
阶段1: 认识AI (Q1, Q2)
  ↓ 叙事逻辑：从抽象认知到具体使用
阶段2: 使用AI (Q3, Q4, Q5, Q6)

## 三、界面布局建议（访谈者视角的智能助手）

### 设计原则

基于"AI做故事引导，人类做深度对话"的人机分工，界面应该遵循：

### 界面使用流程（完整访谈过程）

**第一步：访谈开始**
1. 访谈者输入被访者信息
2. 被访者完成15题测试（或访谈者帮助填写）
3. 引擎生成类型结果：AI探索者

**第二步：开始阶段1（认识AI - Q1）**
1. 访谈者看到"当前讨论：Q1"，题目+答案显示在界面顶部
2. 访谈者转向被访者："Q1你选了'非常同意'，还记得当时怎么考虑的吗？"
3. 被访者回忆："哦对，我当时觉得我能分辨..."
4. 访谈者快速扫视"故事化引导"（不用翻页）
5. 访谈者选择"叙事起点"（用自己的语言）："说到识别AI，你什么时候开始注意到AI的存在？"
6. 被访者开始讲述故事："大概是ChatGPT出来的时候..."
7. 访谈者根据故事内容，决定是否深入到"深化方向"或"反思引导"
8. 访谈者在"访谈记录区"实时记录

**第三步：完成阶段1，进入阶段2（使用AI - Q3）**
1. Q1和Q2讨论完毕，访谈者查看"访谈旅程地图"：阶段1完成，阶段2待讨论
2. 访谈者看到"过渡建议"："你刚才分享了对AI的理解。那在日常生活中，你具体怎么使用AI呢？"
3. 访谈者用自己的语言调整，过渡到阶段2
4. 重复上述流程...

**第四步：完成所有阶段，导出访谈记录**
1. 访谈者点击"导出"
2. 系统生成包含以下内容的访谈报告：
   - 被访者基本信息
   - 15题答案
   - 类型结果
   - 6个阶段的访谈记录
   - 关键发现

### 界面关键特征

1. **信息层次清晰**：
   - 顶部：访谈信息+旅程地图（宏观定位）
   - 中上部：原题+答案（回到原题）
   - 中下部：故事化引导（AI生成的核心价值）
   - 底部：访谈记录（实时保存）

2. **故事化引导分层递进**：
   - 📖 叙事起点（浅层）：激发回忆，容易回答
   - 🔬 深化方向（中层）：具体场景，深入细节
   - 🧩 反思引导（深层）：批判思考，形成理解
   - 🎯 类型视角（可选）：从类型框架切入，提供第二视角

3. **可折叠设计**：
   - "故事化引导"可以折叠，避免信息过载
   - 访谈者可以按需展开查看

4. **访谈者自由度明确**：
   - 每个引导都标注"连接"，说明与原题答案的关系
   - 界面暗示"这是引导思路，不是固定脚本"

### 故事化引导的生成逻辑总结

**核心原则**：
1. **由浅入深**：叙事起点 → 深化方向 → 反思引导
2. **回到原题**：每个引导都与原题答案有明确的连接
3. **激发叙事**：引导语像"讲故事"，不像"考试题"
4. **具体场景**：引导受访者回忆具体的时间、地点、事件
5. **反思闭环**：从过去的故事转向当下的理解

**避免的提问方式**：
- ❌ "如何理解这道题？"
- ❌ "想到了什么具体内容和事件？"
- ❌ "为什么做这个选择？"
- ❌ "有什么困惑的？"

**期望的引导方式**：
- ✅ "你什么时候开始注意到AI的存在？"
- ✅ "第一次意识到'这个应用用了AI'时的情景是什么？"
- ✅ "现在回看，你当时对AI的判断准确吗？"
- ✅ "这种'能用但不坚持'的矛盾，你怎么看？"

## 七、总结：AI做故事引导，人类做深度对话

### 核心定位转变

```
┌─────────────────────────────────────────────────────────────┐
│                                                              │
│  原来的可能误解（❌）                现在的正确理解（✅）      │
│                                                              │
│  被访者 ↔ 引擎界面                 访谈者 ↔ 引擎界面          │
│  (被访者直接交互)                   (访谈者的智能助手)        │
│                                                              │
│  AI作用：                       AI作用：                     │
│  - 实时生成追问                    - 静态生成故事化引导        │
│  - 根据反馈调整                    - 基于测试答案+类型        │
│  - 主导访谈节奏                    - 提供6阶段结构            │
│                                                              │
│  访谈者角色：                     访谈者角色：               │
│  - 执行引擎指令                    - 主导访谈节奏和方向        │
│  - 按脚本提问                      - 判断引导建议价值         │
│  - 收集数据                       - 进行深度对话             │
│                                    - 建立访谈关系             │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

### 4个核心问题的修正

| 问题 | 原来状态 | 修正方案 |
|------|---------|---------|
| 1. 追问建议模板化 | "如何理解、想到了什么、为什么选择" | 故事化引导（叙事起点→深化方向→反思引导） |
| 2. AI生成内容缺语境 | 只有问题，无解释 | 三层信息（连接说明+为什么有效+预期收获） |
| 3. 没有回到原题 | 追问与原题脱节 | 题目+答案始终可见，引导基于原题答案 |
| 4. 缺乏过渡引导 | 阶段间无连接 | 6阶段旅程地图+过渡建议脚本 |

### AI引擎的能力边界

**AI能做的**：
- ✅ 根据测试答案生成人物画像（人格类型判定）
- ✅ 提供6个板块的结构化引导（认识→使用→信任→相处→理解→重新定义）
- ✅ 对每道题提供**故事化引导**（叙事起点→深化方向→反思引导）
- ✅ 结合人格类型，提供类型视角的追问线索

**AI不能做的**：
- ❌ 不进行实时性的智能化访谈提问生成
- ❌ 不根据被访者的现场反馈调整追问
- ❌ 不主导访谈节奏和方向

**人类访谈者的主导角色**：
- ✅ **掌握访谈节奏和方向**（问什么、什么时候问、怎么问）
- ✅ **根据每道题回答进行针对性提问**（用自己的语言，结合现场氛围）
- ✅ **判断引擎建议的价值**（使用、忽略、调整）
- ✅ **建立访谈关系**（共情、倾听、追问）

### 技术实现优先级（10天MVP）

**P0（必须）**：
1. 题目+答案可视化面板
2. 故事化引导引擎（3层：叙事起点→深化方向→反思引导）
3. 访谈记录区

**P1（重要）**：
4. 访谈旅程地图（6阶段进度+过渡建议）
5. 类型视角引导

**P2（可选）**：
6. 简化矛盾检测（3-5个硬编码模式）
7. 界面美化

## 八、快速检查清单（给开发者）

### 核心定位检查

- ✅ 引擎界面是否明确是为**访谈者**设计的工具界面？
- ✅ 是否明确**AI不做实时生成**，只基于测试答案提供静态引导？
- ✅ 是否明确**访谈者主导节奏和方向**？

### 故事化引导检查

- ✅ 是否避免模板化提问（"如何理解、想到了什么、为什么选择"）？
- ✅ 是否提供**故事化引导**（叙事起点→深化方向→反思引导）？
- ✅ 每个引导是否包含**三层信息**（连接说明+为什么有效+预期收获）？
- ✅ 引导语是否像"讲故事"，不像"考试题"？

### 界面呈现检查

- ✅ 是否显示**原题内容+用户答案**（始终可见）？
- ✅ 是否提供**6阶段旅程地图**（进度+过渡建议）？
- ✅ 是否有**访谈记录区**（实时保存）？
- ✅ 界面是否像**专业工具**而非公众用户界面？

### 功能优先级检查（10天限制）

- ✅ P0功能是否完成（题目+答案、故事化引导、访谈记录）？
- ✅ P1功能是否重点做（旅程地图、过渡建议）？
