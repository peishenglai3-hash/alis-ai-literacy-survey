## 🚨 核心问题诊断

### 当前四思考窗口的内容问题

根据图31-32的截图，725迭代已将"三步流程"重构为"四个思考窗口"，但**实际内容**存在三类严重问题：

#### 问题1：关键词缺失（用通用占位符）

**当前状态**（图31）：
```
❌ 当前显示（通用占位符）：

【题目理解】
这道题在问什么？
关键词与核心关注

【经验叙事】
可能的故事入口与访谈方向

【选择解释】
4分·中分段(3-4分)
[通用描述]

【素养关联】
研究关联与注意区分
```

**问题**：
- "关键词与核心关注"是**字段名**，不是实际关键词
- "可能的故事入口与访谈方向"是**标题**，不是实际故事入口
- "研究关联与注意区分"是**标签**，不是实际关联内容

**正确状态**应该：
```
✅ 应该显示（Q1示例）：

【题目理解】
这道题在问什么？
关键词：识别 · 分辨 · 判断
核心关注：
• TA如何理解"AI"
• TA认为什么算"真正使用AI"

【经验叙事】
故事入口：
• 第一次：第一次听说AI是什么时候？
• 典型经历：有没有一次判断AI的经历？
• 变化：你对AI的判断标准有没有变化？

【选择解释】
你的选择：5分
可能意味着：
• 能够识别AI应用
• 对AI有一定判断标准

【素养关联】
本题涉及：
AI识别能力 → AI理解能力 → 技术判断能力
注意区分：描述知识 vs 描述经验判断
```

#### 问题2：素养关联未按题调整

**当前状态**：
所有题的素养关联都显示相同内容（如"AI识别能力 → AI理解能力 → 技术判断能力"），无论该题实际测量什么能力。

**问题**：
- Q1（AI识别）和Q8（结果验证）显示相同的素养关联
- 每道题测量的能力维度不同，素养关联应该不同
- 这是"通用占位符"问题的延续

#### 问题3：语境缺失

**当前状态**：
四个思考模块的内容没有具体对应到每一道题的基本含义。

**问题**：
- 访谈者看到Q1和Q8的内容几乎一样
- 无法帮助访谈者理解"这道题的特殊价值在哪"
- 违背了"扩大访谈者观察能力"的核心定位

### 根本原因

**未提供清晰的Question Schema数据规范**。

v3_725的设计文档只给出了Q1的示例Schema，没有为Q2-Q15提供完整Schema。开发者只能：
1. 用Q1的Schema作为"模板"应用到所有题
2. 或者用"通用占位符"渲染所有题

两种做法都导致了当前的"千题一面"问题。

本文件（及关联的Q6-Q10、Q11-Q15文件）提供：

## 📐 Question Schema 框架规范

### 数据结构定义

```typescript
interface QuestionSchema {
  question_id: string;              // "Q1" - "Q15"
  content: string;                  // 题目文本
  journey_stage: string;            // 6阶段之一
  question_type: string;            // 能力/经验/实践/反思/情境
  measurement_target: string;       // 测量目标
  related_dimension: string;        // 关联的极性维度（E-U/T-V/F-R）

  // 关键词（该题独有，非通用）
  keywords: string[];               // 3-5个关键词

  // 四个思考窗口
  thinking_windows: {
    meaning: {                      // 窗口1：题目理解
      focus_points: string[];       // 核心关注点（3-4个）
      common_misunderstanding: string[];  // 常见误区（1-2个）
    };

    experience: {                   // 窗口2：经验叙事
      story_entries: Array<{
        type: string;               // "第一次" | "典型经历" | "变化节点"
        prompts: string[];          // 1-2个具体提示
      }>;
    };

    choice: {                       // 窗口3：选择解释
      high_score: {                 // 5-7分
        may_mean: string[];         // 可能意味着（2-3个）
        explore_direction: string[];// 探索方向（1-2个）
      };
      mid_score: {                  // 3-4分
        may_mean: string[];
        explore_direction: string[];
      };
      low_score: {                  // 1-2分
        may_mean: string[];
        explore_direction: string[];
      };
    };

    literacy: {                     // 窗口4：素养关联
      ability_chain: string[];      // 能力链（如["AI识别", "→", "AI理解"]）
      distinction: string[];        // 注意区分（如["描述知识", "vs", "经验判断"]）
    };
  };

  // 跨题关联规则
  cross_question_associations: Array<{
    target_question: string;        // "Q3"
    trigger_keywords: string[];     // 触发关键词
    association_note: string;       // 关联说明
  }>;
}
```

### 内容设计原则

#### 原则1：关键词必须是该题独有

❌ 错误（通用）：`keywords: ["识别", "分辨", "判断"]`（所有题都用这套）

✅ 正确（独有）：
- Q1: `["识别", "分辨", "判断"]`（关于AI识别）
- Q3: `["使用", "场景", "动机"]`（关于使用动机）
- Q8: `["验证", "检查", "核实"]`（关于结果验证）

#### 原则2：素养关联必须对应测量目标

❌ 错误（通用）：所有题都显示 `AI识别 → AI理解 → 技术判断`

✅ 正确（对应）：
- Q1（AI识别）: `AI识别能力 → AI理解能力`
- Q8（结果验证）: `结果验证能力 → 批判性思维`
- Q11（隐私风险）: `风险意识 → 隐私保护能力`

#### 原则3：经验叙事必须结合题目语境

❌ 错误（通用）：所有题的故事入口都是"第一次接触AI"

✅ 正确（语境化）：
- Q1（AI识别）: "第一次判断AI的经历"
- Q5（协作意愿）: "调试AI的经历"
- Q11（隐私风险）: "担心隐私泄露的经历"

## 📝 Q1 完整Schema

### 基本信息

```yaml
question_id: "Q1"
content: "我通常能够判断，一个应用或服务是否真正使用了AI"
journey_stage: "认识AI"
question_type: "能力"
measurement_target: "AI识别能力"
related_dimension: "E-U（探索者-实用者）"
```

### 关键词（该题独有）

```json
["识别", "分辨", "判断", "真正使用"]
```

**设计说明**：
- "识别"：能否察觉AI的存在
- "分辨"：能否区分AI和非AI
- "判断"：是否有明确的判断标准
- "真正使用"：对"AI"的定义边界

### 思考窗口1：题目理解

```json
{
  "focus_points": [
    "TA如何理解'AI'这个概念",
    "TA认为什么算'真正使用AI'（vs 仅作为噱头）",
    "TA的判断标准是什么（技术细节 vs 使用体验）",
    "TA有没有质疑过题目中'真正使用'的表述"
  ],
  "common_misunderstanding": [
    "把AI等同于机器人或ChatGPT",
    "认为'使用了AI'就是'界面有AI字样'"
  ]
}
```

### 思考窗口2：经验叙事

```json
{
  "story_entries": [
    {
      "type": "第一次",
      "prompts": [
        "第一次判断某个应用是否用了AI是什么时候？",
        "第一次明确'这是AI'的瞬间"
      ]
    },
    {
      "type": "典型经历",
      "prompts": [
        "有没有判断对了/判断错了的经历？",
        "遇到过'看起来像AI但其实不是'的应用吗？"
      ]
    },
    {
      "type": "变化",
      "prompts": [
        "你对'什么是AI'的判断标准有没有变化？"
      ]
    }
  ]
}
```

### 思考窗口3：选择解释

```json
{
  "high_score": {
    "score_range": [5, 6, 7],
    "may_mean": [
      "能够主动识别AI应用",
      "有较明确的判断标准",
      "关注技术实现细节"
    ],
    "explore_direction": [
      "这种判断能力来自哪里？（技术背景/职业/兴趣）",
      "判断依据是技术特征还是使用体验？"
    ]
  },
  "mid_score": {
    "score_range": [3, 4],
    "may_mean": [
      "对AI识别有一定把握，但标准可能模糊",
      "部分场景能判断，部分场景不确定"
    ],
    "explore_direction": [
      "什么时候能确定？什么时候不确定？",
      "不确定的时候会怎么处理？"
    ]
  },
  "low_score": {
    "score_range": [1, 2],
    "may_mean": [
      "较少主动判断应用是否用了AI",
      "可能通过使用体验感知，不关注技术细节"
    ],
    "explore_direction": [
      "你觉得AI是什么样的？会用什么方式描述？",
      "如果让你判断，你会看什么？"
    ]
  }
}
```

### 思考窗口4：素养关联

```json
{
  "ability_chain": [
    "AI识别能力", "→", "AI理解能力", "→", "技术判断能力"
  ],
  "distinction": [
    "描述知识", "vs", "描述经验判断",
    "（TA说'知道AI是什么' vs TA真的能判断）"
  ]
}
```

**设计说明**：
本题是AI素养的**起点**——如果不能识别AI，后续的理解、使用、批判都无从谈起。
"描述知识 vs 描述经验判断"是访谈者需要重点区分的：被访者可能"知道AI概念"但"实际判断不准"。
