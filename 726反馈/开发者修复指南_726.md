## ⚠️ 给开发者的核心提醒

### 本次反馈与以往不同

**本次反馈的核心不是"添加新功能"，而是"删除旧内容"**。

如果你只能做一件事，请做这件事：

> **全局搜索"AI探索者"、"AI实践家"、"AI验证者"等8种旧人格类型名称，把所有相关代码、数据、组件全部删除。**

### 针对开发者习惯的特别提示

我们注意到一个反复出现的模式：**开发者倾向于"添加新功能"而不"删除旧代码"**。

本次反馈中，这种行为会导致问题无法解决。例如：
- 如果只在UI层叠加新的"ETF"类型，但旧的"AI探索者"代码仍然存在 → 结果页仍然显示大段旧文字
- 如果只添加新的"四思考窗口"组件，但旧的"追问建议"组件不删除 → 访谈界面仍然信息过载

**因此，本次执行的核心原则是：先删除，再添加。**

```javascript
// 基于cross_question_associations字段的触发逻辑
function checkCrossQuestionAssociations(questionId, interviewAnswer) {
  const schema = getQuestionSchema(questionId);
  const associations = [];

  for (const rule of schema.cross_question_associations) {
    const hasKeyword = rule.trigger_keywords.some(kw =>
      interviewAnswer.toLowerCase().includes(kw.toLowerCase())
    );

    if (hasKeyword) {
      associations.push({
        target_question: rule.target_question,
        association_note: rule.association_note
      });
    }
  }

  return associations;
}
```

## ⚠️ 常见陷阱与避坑指南

### 陷阱1：保留旧代码作为"备份"或"注释"

**错误做法**：
```python
# def determine_old_type(...):  # 旧代码，先注释掉，以后可能用
#     ...
```

**正确做法**：
```python
# 直接删除，不留任何痕迹
# 如果需要备份，使用git历史，而不是代码注释
```

### 陷阱2：只删除UI层，不删除数据层

**错误做法**：
- 删除了前端`<OldPersonalityCard />`组件
- 但保留了`old_personality_types.json`数据文件
- 后端API仍然返回`personality_description`字段

**正确做法**：
- 前端组件、后端代码、数据文件、数据库表**全部删除**
- 用grep命令验证没有残留

### 陷阱3：添加新功能时不删除旧功能

**错误做法**：
- 添加了新的`SimplifiedPolarityChart`组件
- 但旧的6条柱形图组件仍然存在
- 结果页同时渲染两个图表

**正确做法**：
- 添加新组件的同时，**立即删除**对应的旧组件
- 在git commit中同时包含"添加新组件"和"删除旧组件"

### 陷阱4：路由守卫不生效

**可能原因**：`ScrollToTop`组件放在`Router`外部。

**错误做法**：
```jsx
<ScrollToTop />  {/* ❌ 在Router外部 */}
<Router>
  <Routes>...</Routes>
</Router>
```

**正确做法**：
```jsx
<Router>
  <ScrollToTop />  {/* ✅ 在Router内部 */}
  <Routes>...</Routes>
</Router>
```

### 陷阱5：Question Schema数据格式不一致

**错误做法**：手动编写15题数据时，字段名不一致（如`focus_points` vs `focusPoints`）。

**正确做法**：严格遵循议程3框架文档中的TypeScript接口定义，所有字段使用下划线命名（snake_case）。

## 📞 常见问题

### Q1：如果删除旧代码后出现报错怎么办？

**A**：这是正常的。删除后需要立即用新代码替代。报错说明还有未清理的引用。继续搜索并删除相关引用，直到没有报错。

### Q2：如果不确定某个代码是否属于"旧代码"，怎么办？

**A**：执行grep搜索。如果该代码引用了"AI探索者"等旧类型名，或者引用了"strengths"、"weaknesses"等旧字段名，就必须删除。如果仍然不确定，参考议程1文档中的"删除指令清单"。

### Q3：Question Schema数据太多，可以只用Q1-Q5吗？

**A**：不可以。15题的Schema必须全部填充，否则用户在做Q6-Q15时看到的仍然是通用占位符。如果时间紧张，优先完成任务1-3，然后集中精力做任务4。

### Q4：结果页的8类型characteristics数据从哪里来？

**A**：详见议程1文档中的"`type_characteristics.js`"代码块，包含8种类型的完整数据。直接复制即可。

### Q5：页面跳转Bug修复后，测试时发现某些场景仍然不回到顶部？

**A**：这些场景可能是"同路由内的状态切换"（如Q1→Q2不是路由变化，而是状态变化）。对于这种情况，需要在组件内补充`useEffect`，详见任务1的Step 3。
