# AI素养访谈引擎 - 版本修改说明

## 文档信息
- **版本迭代**: v1.0（问卷系统）→ v2.0（访谈引擎）
- **修改性质**: 产品定位升级 + 交互逻辑重构
- **修改目标**: 从"AI素养测评工具"升级为"AI素养反思性访谈引擎"
- **开发基础**: 在现有框架基础上进行架构调整，非推倒重来

---

## 一、版本迭代背景：为什么需要修改？

### 1.1 当前版本（v1.0）的技术评估

**已有优势**（保留并增强）：
- ✅ 基础题目展示逻辑完整
- ✅ Likert量表交互基础功能正常
- ✅ 结果计算和展示框架已搭建
- ✅ 前后端数据通信链路已打通

**核心问题**（需要架构调整）：
| 问题类型 | 具体表现 | 技术原因 |
|---------|---------|---------|
| **产品定位偏差** | 当前实现为"问卷测评工具"，缺失"访谈引擎"核心逻辑 | 测试终点停留在数据展示，未进入反思性交互 |
| **交互流程割裂** | 单题展示模式，无法形成"整体自我画像"的认知过程 | 缺少MBTI式整体判断→类型认同→反思讨论的完整链路 |
| **数据价值未充分挖掘** | 测试结束=产品结束，访谈数据未生成 | 缺少追问图谱、经验记录、矛盾检测等访谈机制 |
| **研究目标未实现** | 无法生成质性研究所需的访谈材料 | 缺少从量化结果到质性叙事的转化机制 |

### 1.2 为什么要升级为"访谈引擎"？

**科研目标的变化**：
- **v1.0目标**：收集AI素养数据，生成群体统计报告
- **v2.0目标**：通过量化测试触发个体反思，生成深度访谈材料

**技术含义的变化**：
```
v1.0技术路径：
15道题 → 数据收集 → 维度得分 → 类型标签 → 展示结束

v2.0技术路径：
15道题 → 风格框架建立 → 6阶段认知旅程 → 针对性追问 → 矛盾检测 → 访谈记录 → AI素养重构
```

**核心变化**：
- 测试不再是终点，而是**认知旅程的起点**
- 类型标签不再是结果，而是**反思讨论的认知框架**
- 交互不再是单向展示，而是**双向追问对话**

## 二、核心理念转变：技术架构如何响应？

### 2.1 从"问卷逻辑"到"认知旅程逻辑"

**v1.0架构问题**：
```javascript
// 当前逻辑：逐题展示
Question 1 → 用户回答 → 下一题
Question 2 → 用户回答 → 下一题
...
Question 15 → 用户回答 → 生成结果 → 结束
```

这种设计符合"数据收集"目标，但不符合"自我认知"目标：
- 用户无法形成整体判断
- 缺少"类型认同"过程
- 无法引发反思

**v2.0架构调整**：
```javascript
// 新逻辑：整体测试 → 类型框架 → 认知旅程

阶段1：整体测试（一次性展示15题，快速完成）
阶段2：类型框架建立（生成AI协作风格，作为认知框架）
阶段3：6阶段认知旅程（基于风格框架，重新经历15题的叙事路径）
阶段4：旅程回望（整合发现，重构AI理解）
```

### 2.2 风格框架的重新定位

**v1.0理解**：
```
风格类型 = 测量结果（终点）
```

**v2.0理解**：
```
风格类型 = 认知框架（起点）

作用：
1. 帮助用户理解"我的AI交互倾向"
2. 作为后续追问的理解框架
3. 引导用户有意识地反思自己的AI实践
```

**技术实现变化**：
```python
# v1.0: 类型作为展示数据
def calculate_style(scores):
    style = determine_style(scores)
    return {"type": style, "scores": scores}  // 直接返回

# v2.0: 类型作为认知框架
def establish_framework(scores):
    style = determine_style(scores)
    return {
        "framework_type": style,
        "framework_description": get_style_profile(style),
        "cognitive_lenses": extract_lenses(style),  // 提取认知视角
        "journey_plan": generate_journey_plan(style)  // 生成个性化旅程
    }
```

### 2.3 15道题的重新定位：从"数据项"到"旅程路标"

**v1.0理解**：
```
Q1-Q15 = 15个测量指标
目的：计算维度得分
```

**v2.0理解**：
```
Q1-Q15 = 6阶段认知旅程的路标

叙事结构：
第一阶段：认识AI (Q1, Q2)
第二阶段：使用AI (Q3, Q4, Q5, Q6)
第三阶段：信任AI (Q7, Q8, Q9, Q12)
第四阶段：与AI相处 (Q10, Q11, Q14)
第五阶段：理解AI (Q10, Q11 - 重复探讨)
第六阶段：重新定义AI (Q14, Q15 - 重复探讨)
```

**技术实现变化**：
```python
# v1.0: 题目仅用于计算
question_weights = {
    "Q1": 0.5,
    "Q2": 0.5,
    ...
}

# v2.0: 题目作为旅程节点
journey_stages = {
    "stage_1": {
        "name": "认识AI",
        "questions": ["Q1", "Q2"],
        "narrative_goal": "探索用户如何认识和理解AI",
        "follow_up_strategy": "认知框架追问",
        "entry_question": "作为'AI协作者'，你如何判断一个应用真正使用了AI？"
    },
    ...
}
```

## 三、具体修改点及技术原因

### 3.1 测试页面交互调整

**修改内容**：
- **从**：单题独立页面展示
- **到**：15道题整体展示，滚动完成

**技术原因**：

1. **认知科学依据**：
   - MBTI等成熟测试采用整体展示，目的是让用户形成"整体自我判断"
   - 逐题展示容易让用户陷入"每题单独思考"，无法形成连贯的自我画像

2. **数据质量考虑**：
   - 整体展示更接近"直觉式回答"，减少过度思考带来的数据偏移
   - 用户可以基于整体印象快速完成，符合"类型测试"而非"能力考试"的定位

3. **用户体验优化**：
   - 减少页面切换次数，降低交互疲劳
   - 用户可以随时回看修改，形成"整体调整"而非"单次锁定"

**技术实现建议**：
```vue
<!-- 推荐实现方式 -->

  <div class="questionnaire-container">
    <div class="test-header">
      <h2>发现你的AI交互类型</h2>

      <p>没有标准答案，依据你的真实经验选择</p>
```

### 3.2 Likert量表调整为7点制

**修改内容**：
- **从**：6点量表（1-6，无中立选项）
- **到**：7点量表（1-7，包含"中立/不确定"）

**技术原因**：

1. **量表设计标准**：
   - 标准Likert量表通常为5点或7点
   - 7点量表提供更精细的区分度
   - 必须包含中立位置，以反映"不确定/未形成稳定态度"的真实状态

2. **数据真实性**：
   - AI使用经验中，很多场景下用户确实处于"不确定"状态
   - 强制选择偏向会导致数据偏移
   - "中立"本身就是有价值的AI素养数据（代表认知未成型）

3. **类型判断准确性**：
   - 中立选项能更准确地区分"强烈倾向"与"模糊倾向"
   - 避免将"不确定者"错误归类为"偏向者"

**技术实现建议**：
```javascript
const LIKERT_SCALE = [
  { value: 1, label: "非常不同意" },
  { value: 2, label: "比较不同意" },
  { value: 3, label: "有点不同意" },
  { value: 4, label: "中立 / 不确定" },  // 新增
  { value: 5, label: "有点同意" },
  { value: 6, label: "比较同意" },
  { value: 7, label: "非常同意" }
];
```

### 3.3 移除选项解释

**修改内容**：
- **从**：点击展开查看每个选项含义
- **到**：仅显示"非常不同意"到"非常同意"

**技术原因**：

1. **认知负荷考虑**：
   - 用户本身理解"不同意→同意"的语义
   - 重复解释增加阅读负担，降低测试流畅度

2. **回答真实性**：
   - 过度解释会引发用户"分析选项差异"而非"依据经验回答"
   - MBTI类测试不解释选项，强调直觉式选择

3. **界面简洁性**：
   - 减少交互层级，提升用户体验

**技术实现建议**：
```vue
<!-- 不需要展开交互，直接显示 -->
<div class="likert-options">
  <label v-for="option in likertOptions" :key="option.value">
    <input type="radio" :name="questionId" :value="option.value">
    <span>{{ option.label }}</span>
  </label>
</div>
```

### 3.4 结果页面从"数据报告"转向"类型反馈"

**修改内容**：
- **从**：显示各维度分数（如"识别AI 100，使用AI 40"）
- **到**：显示类型描述、优势盲区、反思入口

**技术原因**：

1. **用户认同感**：
   - 数字分数无法引发"这像不像我"的思考
   - 类型描述（如"AI探索者：你倾向于主动尝试AI..."）更容易产生认同或质疑

2. **访谈入口**：
   - 数字分数无法作为对话起点
   - 类型描述可以直接追问"这个结果符合你的感觉吗？"，进入访谈

3. **科研价值**：
   - 分数是量化结果，描述才是质性研究的起点
   - 用户对类型的反馈（认同/质疑/修正）才是研究材料

**技术实现建议**：

### 3.5 新增访谈引擎核心逻辑

**修改内容**：
- **从**：测试结束 = 产品结束
- **到**：测试结束 = 访谈开始

**新增核心模块**：

#### 1. JourneyEngine（认知旅程引擎）
```python
class JourneyEngine:
    """管理6阶段认知旅程的规划和执行"""

    def plan_journey(self, user_framework):
        """基于用户风格框架，生成个性化旅程计划"""
        stages = [
            {
                "id": 1,
                "name": "认识AI",
                "questions": ["Q1", "Q2"],
                "entry_question": self._generate_entry_question(user_framework, "Q1"),
                "framework_lens": self._extract_framework_lens(user_framework, "stage_1")
            },
            # ... 其他5个阶段
        ]
        return stages

    def start_stage(self, stage_id):
        """启动一个认知阶段"""
        stage = self.stages[stage_id - 1]
        return {
            "stage_info": stage,
            "current_focus": stage["entry_question"],
            "framework_card": self._generate_framework_card(user_framework, stage_id)
        }
```

#### 2. QuestionSpecificFollowUpExecutor（针对性追问执行器）
```python
class QuestionSpecificFollowUpExecutor:
    """针对每道题的5层追问序列"""

    def execute_follow_up_sequence(self, question_id, user_response):
        """执行5层追问序列"""
        sequence = [
            {
                "layer": 1,
                "type": "experience_elicitation",
                "prompt": f"能否分享一个具体的例子，说明你在'{question_context}'中的体验？"
            },
            {
                "layer": 2,
                "type": "framework_connection",
                "prompt": f"从'{user_framework}'的角度看，你觉得这段体验反映了什么？"
            },
            {
                "layer": 3,
                "type": "contradiction_detection",
                "prompt": self._detect_contradiction(question_id, user_response)
            },
            {
                "layer": 4,
                "type": "ai_literacy_bridge",
                "prompt": f"这段经历如何影响你对AI的理解？"
            },
            {
                "layer": 5,
                "type": "reflection_deepening",
                "prompt": "现在回看这段经历，你有什么新的发现？"
            }
        ]
        return sequence
```

#### 3. ContradictionDetector（矛盾检测器）
```python
class ContradictionDetector:
    """检测用户回答中的矛盾并引发反思"""

    def detect_contradictions(self, user_responses):
        """检测跨题回答的逻辑矛盾"""
        contradictions = []

        # 示例：Q3高分（能用AI完成事情）+ Q5低分（遇到不理解就放弃）
        if user_responses["Q3"] >= 6 and user_responses["Q5"] <= 3:
            contradictions.append({
                "type": "cross_question",
                "questions": ["Q3", "Q5"],
                "description": "工具使用能力 vs 协作意愿",
                "prompt": "你说能用AI完成事情，但遇到不理解时会放弃。这种矛盾你怎么看？"
            })

        return contradictions
```

#### 4. JourneyStateManager（旅程状态管理器）
```python
class JourneyStateManager:
    """追踪用户在6阶段旅程中的进展"""

    def update_progress(self, stage_id, discoveries):
        """更新旅程进度并记录发现"""
        self.progress["completed_stages"].append(stage_id)
        self.progress["discoveries"].extend(discoveries)

        return {
            "current_stage": self._get_next_stage(),
            "progress_percentage": len(self.progress["completed_stages"]) / 6 * 100,
            "discoveries_so_far": self.progress["discoveries"]
        }
```

## 四、新架构的技术优势

### 4.1 数据价值大幅提升

**v1.0数据产出**：
- 15个Likert响应值
- 4个维度得分
- 1个类型标签

**v2.0数据产出**：
- 15个Likert响应值
- 4个维度得分
- 1个类型标签
- **6个认知阶段的深度访谈记录**

- **矛盾检测发现的认知冲突**
- **旅程回望时的自我反思**
- **AI素养重构叙事**

**科研价值对比**：
```
v1.0: 可以做群体统计，描述"AI素养分布"
```

```
测试 → 看结果 → 离开
```

**v2.0体验路径**：
```

（连贯式体验）
```

### 4.3 产品定位的差异化

**v1.0市场定位**：

**v2.0市场定位**：
- "AI素养反思工具"（全球首创）

## 八、开发者沟通要点

### 8.1 核心问题回答

**Q: 为什么不直接用v1.0，而是要升级？**

A: v1.0实现了"AI素养测评"功能，但我们的科研目标是"AI素养访谈"。两者区别：
- 测评：收集数据，生成统计报告
- 访谈：通过测试触发反思，生成质性研究材料

当前v1.0可以告诉我们"用户的AI素养分布"，但无法回答"用户的AI素养如何形成、如何理解、如何演化"。后者才是我们的研究目标。

**Q: v2.0是否需要推倒重来？**

A: 不需要。v2.0在v1.0基础上扩展：
- 前端组件复用率约70%
- 后端逻辑复用率约60%
- 数据库复用率约80%
- 新增开发量约占项目总量的30-40%

**Q: 开发周期多久？**

A: 建议分3个迭代版本：
- v1.5（1-2周）：测试体验优化
- v1.8（2-3周）：访谈引擎基础版
- v2.0（3-4周）：完整访谈引擎
- **总计**：6-9周在v1.0基础上完成升级

**Q: 最大的技术难点在哪里？**

A: 两个模块：
1. **JourneyEngine**：需要根据用户风格框架生成个性化旅程计划
2. **QuestionSpecificFollowUpExecutor**：需要实现5层追问序列的动态生成

这两个模块都需要一定的业务逻辑理解，但技术实现本身不复杂（主要是条件判断和文本组合）。

### 8.2 技术支持承诺

我们为开发者提供：
1. ✅ 完整的技术规格文档（API、数据库、算法）
2. ✅ 可交互的HTML原型（可视化展示期望行为）
3. ✅ 详细的15题叙事结构映射（每道题的追问方向）
4. ✅ 8种风格的完整画像（约24000字，可直接用于类型描述）
5. ✅ 随时技术咨询支持（设计意图、业务逻辑答疑）

## 九、总结：从"问卷系统"到"访谈引擎"的升级意义

### 9.1 产品定位升级

```
v1.0: AI素养测评工具
（与市场上"AI素养调查"同质化）

v2.0: AI素养反思性访谈引擎
（全球首创，填补质性研究工具空白）
```

```
v1.0数据: 15个数字 + 1个标签
（仅支持量化统计）

v2.0数据: 15个数字 + 1个框架 + 6阶段访谈记录 + 矛盾发现 + 反思叙事
（支持质性分析，可发表高水平研究论文）
```

### 9.3 用户体验升级

```
v1.0: 测试 → 看结果 → 离开
（单次使用，无持续价值）

v2.0: 测试 → 理解风格 → 认知旅程 → 反思整合 → 带着新理解离开
（深度体验，产生认知价值）
```

### 9.4 开发可行性

```
复用基础：70%（前端）+ 60%（后端）+ 80%（数据库）
新增开发：30-40%项目总量
开发周期：6-9周（在v1.0基础上）
技术难度：中等（主要是业务逻辑，非技术挑战）
```

我们相信，在开发者现有框架的基础上，通过6-9周的增量开发，可以实现一个**全球首创的AI素养反思性访谈引擎**，为AI素养研究提供独特的质性研究工具。
