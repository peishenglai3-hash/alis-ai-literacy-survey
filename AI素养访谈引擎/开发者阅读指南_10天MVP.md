## 🎯 一、项目核心目标（2分钟理解）

### 我们要做什么？

**一句话**：开发一个工具，让社会学大二学生能够通过它对受访者进行深度访谈。

**核心流程**：
```
学生访问工具 → 受访者完成15题测试 → 工具生成AI交互类型 → 学生基于类型进行针对性追问 → 记录访谈内容
```

**关键点**：
- ✅ **工具用户是访谈者**（社会学学生），不是受访者
- ✅ 受访者是访谈对象（被学生访谈的人）
- ✅ 工具的作用是**辅助访谈**，提供追问线索和记录功能
- ✅ 最终产出是**访谈记录**（研究数据），不是测试结果

### 与传统测试的区别

| 传统问卷/测试 | 我们的访谈引擎 |
|-------------|--------------|
| 用户自己做题，看到结果，离开 | 访谈者引导受访者做题，然后开始访谈 |
| 结果是数字/类型标签 | 结果是**访谈线索**（从哪里开始追问） |
| 测试结束=产品结束 | 测试只是起点，**访谈才是重点** |
| 产出量化数据 | 产出**质性访谈材料** |

**简单理解**：
- 传统测试 = "给你测个结果"
- 我们的引擎 = "帮助访谈者和受访者进行深度对话"

## 💡 二、设计理念（10分钟理解）

### 为什么需要这个工具？

**社会学研究的挑战**：
- 学生直接访谈受访者："你平时怎么用AI？" → 受访者不知道从何说起
- 访谈缺乏结构：想到哪问到哪，难以深入
- 访谈记录杂乱：后期整理困难

**我们的解决方案**：
1. **15题测试作为"破冰"**：让受访者快速思考自己的AI使用经历
2. **类型描述作为"话题起点"**："你是AI探索者，你倾向于主动尝试AI..." → 引发受访者认同或质疑
3. **针对性追问作为"访谈线索"**：工具告诉学生"可以从这里开始深入追问"
4. **结构化记录作为"研究产出"**：访谈内容自动组织，后期易于分析

### 核心理念：类型不是"标签"，是"对话框架"

❌ **错误理解**：
```
测试 → 得出"AI探索者" → 告诉受访者"你是探索者" → 访谈结束
```

✅ **正确理解**：
```
测试 → 得出"AI探索者" → 访谈者说"你是AI探索者..." → 受访者"是吗？我确实喜欢尝试新工具"
→ 访谈者追问"能分享一个最近尝试的例子吗？" → 深度对话开始
```

**关键转变**：
- 类型不是用来**定义**受访者，而是用来**引发讨论**
- 类型不是访谈的**终点**，而是访谈的**起点**
- 类型描述帮助受访者**回忆和反思**自己的AI实践

### 15道题的6个阶段（快速理解）

15道题不是散乱的，而是有**叙事结构**：

```
📍 阶段1: 认识AI (Q1, Q2)
"你如何判断一个应用是否用了AI？"
→ 目标：了解受访者对AI的技术理解

📍 阶段2: 使用AI (Q3, Q4, Q5, Q6)
"你通常用AI做什么？遇到不理解会调整表达吗？"
→ 目标：了解受访者的使用习惯和协作意愿

📍 阶段3: 信任AI (Q7, Q8, Q9, Q12)
"你能判断AI什么时候值得相信吗？"
→ 目标：了解受访者的信任判断机制

📍 阶段4: 与AI相处 (Q10, Q11, Q14)
"你会考虑AI的社会影响和隐私问题吗？"
→ 目标：了解受访者对AI外部影响的思考

📍 阶段5: 理解AI (Q10, Q11的深入探讨)
→ 从个人视角扩展到社会视角

📍 阶段6: 重新定义AI (Q14, Q15的深入探讨)
→ 整合整个旅程，重新理解"AI是什么"
```

**访谈策略**：
- 测试完成后，访谈者知道受访者的类型（如"AI探索者"）
- 工具提供"从探索者框架看，Q1高分说明他了解AI能力边界"
- 访谈者可以追问："作为探索者，你如何判断一个应用真正使用了AI？"
- 受访者基于具体经验分享，访谈进入深度对话

## 🚀 三、10天MVP功能优先级（5分钟理解）

### ⚠️ 关键约束

- **时间限制**：10天
- **使用者**：社会学大二学生（非技术人员）
- **使用场景**：实地访谈（可能是面对面、视频、语音）
- **核心目标**：能够进行**有效的访谈**并记录内容

### 功能分级

#### 🔴 P0 - 绝对必须（第1-5天）

没有这些，**无法进行访谈**：

1. **15题整体展示的测试页面**
   - ✅ 一次性显示15道题（可滚动）
   - ✅ 7点Likert量表（1-7，含中立选项）
   - ✅ 简洁的开始页面："发现你的AI交互类型"
   - ✅ 提交后生成结果

2. **类型描述结果页**
   - ✅ 显示类型名称（如"AI探索者"）
   - ✅ 显示类型描述（1-2段话，说明这个类型的特点）
   - ✅ 显示优势/盲区（简短列表）
   - ✅ **关键**：询问"这个结果符合你的感觉吗？"（非常符合/部分符合/不太符合）
   - ✅ **关键**：开放文本框"为什么？请分享想法"

3. **类型到追问的映射逻辑**
   - ✅ 根据类型+具体题目，生成追问建议
   - ✅ **简化实现**：预设追问模板（不需要复杂AI生成）
   - ✅ 示例：类型"AI探索者" + Q1高分 → 追问"作为探索者，你如何判断一个应用真正用了AI？"

4. **访谈记录界面**
   - ✅ 显示当前访谈阶段（如"阶段2：使用AI - 正在探讨Q3"）
   - ✅ 显示追问建议列表（3-5个预设追问）
   - ✅ 访谈者可以手动记录受访者回复（文本输入）
   - ✅ 保存功能（保存到本地或云端）

**P0验收标准**：
- 社会学学生能够独立完成：引导受访者测试 → 查看类型 → 使用追问线索 → 记录访谈
- 访谈过程流畅，不出现技术故障
- 访谈记录能够保存并导出

#### 🟡 P1 - 重要优化（第6-8天）

有了这些，**访谈质量显著提升**：

5. **矛盾检测提示**
   - ✅ 检测跨题逻辑矛盾（如Q3高分+Q5低分）
   - ✅ 在访谈界面显示："发现可能矛盾：Q3说能用AI完成，Q5说遇到困难会放弃"
   - ✅ 提供追问建议："这种矛盾你怎么看？"

6. **访谈进度可视化**
   - ✅ 显示6个阶段的进展（✅已完成 🔄进行中 ⏳未开始）
   - ✅ 让访谈者知道"我们讨论到哪了"

7. **类型知识卡片**
   - ✅ 在访谈界面持续显示当前类型的核心特点
   - ✅ 帮助访谈者记住"从什么框架提问"

8. **访谈记录导出**
   - ✅ 导出为Word/PDF格式
   - ✅ 方便学生后期整理和分析

#### 🟢 P2 - 锦上添花（第9-10天）

时间允许再做：

9. **旅程回望功能**
   - ✅ 访谈结束时，显示"我们在这次旅程中发现了什么"
   - ✅ 整合所有关键发现

10. **界面美化**
    - ✅ 优化颜色、字体、间距
    - ✅ 但**不影响功能的前提下**

### 功能取舍建议

如果10天实在紧张，**优先保证P0，P1和P2可适当简化**：

**P0不可妥协**：这是访谈工具的底线
**P1可简化**：
- 矛盾检测可以手动列出常见模式（3-5种），不需要全覆盖
- 进度可视化可以简单文字显示（"当前：阶段2/6"），不需要复杂图形
- 知识卡片可以简化为类型名称+一句话描述

**P2可延后**：这些可以下次迭代再补充

- ✅ **简单实用**：选择你熟悉的技术，不要追求新颖
- ✅ **快速部署**：社会学学生需要能方便使用
- ✅ **易于维护**：访谈期间可能需要快速调整

### 数据结构建议（最小化）

**必要的数据库表**：

1. **users（访谈者）**
```sql
- id
- name（学生姓名）
- email（联系方式）
- created_at
```

2. **interview_sessions（访谈会话）**
```sql
- id
- interviewer_id（哪个学生）
- respondent_notes（受访者备注，如"大二-工科-张三"）
- test_responses（15题答案 JSON）
- result_type（生成的类型，如"AI探索者"）
- interview_records（访谈记录 JSON）
- created_at
- updated_at
```

3. **follow_up_templates（追问模板）**
```sql
- id
- type_pattern（适用类型，如"AI探索者"）
- question_id（对应题目，如"Q1"）
- score_condition（分数条件，如">=5"）
- follow_up_prompt（追问文本，如"作为探索者，你如何判断..."）
```

**不需要复杂**：
- ❌ 用户认证系统（可以简单输入姓名即可）
- ❌ 权限管理（所有人都能看到所有访谈）
- ❌ 复杂的关联表（JSON够用）

### 核心算法简化

**风格判定逻辑**：
```python
# 简化版：基于关键题目直接判断
def determine_style(responses):
    # 示例：AI探索者的简化判断
    if responses["Q1"] >= 5 and responses["Q2"] >= 5 and responses["Q6"] >= 5:
        return "AI探索者"

    # 示例：AI实践家的简化判断
    if responses["Q3"] >= 5 and responses["Q4"] >= 5 and responses["Q5"] >= 5:
        return "AI实践家"

    # ... 其他类型
    # 如果都不符合，返回"AI平衡者"
```

**追问生成逻辑**：
```python
# 简化版：从模板库中匹配
def get_follow_up_suggestions(responses, result_type, current_question):
    suggestions = []

    # 从数据库查询匹配的追问模板
    templates = query_follow_up_templates(
        type_pattern=result_type,
        question_id=current_question,
        score_condition=responses[current_question]
    )

    for template in templates:
        suggestions.append(template["follow_up_prompt"])

    return suggestions[:5]  # 最多返回5个
```

**矛盾检测逻辑**：
```python
# 简化版：硬编码常见矛盾模式
def detect_contradictions(responses):
    contradictions = []

    # 模式1：工具使用能力 vs 协作意愿
    if responses["Q3"] >= 5 and responses["Q5"] <= 3:
        contradictions.append({
            "type": "能力-意愿矛盾",
            "questions": ["Q3", "Q5"],
            "prompt": "你说能用AI完成事情，但遇到不理解时会放弃。这种矛盾你怎么看？"
        })

    # 模式2：高信任 vs 低验证
    if responses["Q7"] >= 5 and responses["Q8"] <= 3:
        contradictions.append({
            "type": "信任-验证矛盾",
            "questions": ["Q7", "Q8"],
            "prompt": "你愿意信任AI处理复杂问题，但通常不验证结果。为什么？"
        })

    return contradictions
```

## ❓ 七、FAQ（常见疑问）

### Q1: 为什么要15题整体展示，不能一题一题来吗？

**A**: 可以一题一题，但整体展示更好：
- ✅ 受访者能看到"这是一个完整的测试"，形成整体判断
- ✅ 类似MBTI的体验，更符合"类型测试"而非"能力考试"
- ✅ 可以回看修改，减少"答错了"的焦虑

**如果时间紧张**：可以先实现一题一题展示，后续再改。但这是P1优化，不是P0必须。

---

### Q2: 为什么必须是7点Likert？6点不行吗？

**A**: 7点是学术标准：
- ✅ 包含中立选项（"不确定"），数据更真实
- ✅ 符合Likert量表设计规范
- ✅ "中立"本身是有价值的AI素养数据

**如果时间紧张**：可以用6点，但需要在说明文档中解释"为什么没有中立选项"。建议还是7点。

---

### Q3: 访谈引擎必须用AI生成追问吗？不能用预设模板吗？

**A**: **不需要AI，预设模板更好**：
- ✅ 10天时间紧，AI集成复杂且不稳定
- ✅ 预设模板质量可控，符合访谈逻辑
- ✅ 我们已经准备好了详细的追问方向（见`AI_Collaboration_Style_Mapping.md`）

**建议**：先实现30-50个预设追问模板，覆盖8种类型×关键题目。后续可以再扩展。

---

### Q4: 如果受访者的类型不典型，怎么办？

**A**: **这是正常且有价值的情况**：
- ✅ 结果页询问"这个结果符合你的感觉吗？"就是为了处理这个问题
- ✅ 如果受访者说"不太符合"，访谈者可以追问："你觉得哪里不准确？"
- ✅ **这个"质疑类型"的过程，正是深度访谈的起点**

**示例**：
- 工具说："你是AI探索者"
- 受访者："不对，我不喜欢尝试新工具"
- 访谈者追问："那你在Q1和Q2中选择了'同意'，能说说为什么吗？"
- 受访者："我知道AI在哪里，但我不会主动去尝试"
- 访谈者："这很有意思，你是'观察者'而非'探索者'..."
- **深度对话开始**

**关键**：类型是"话题起点"，不是"绝对标签"。

---

### Q5: 社会学学生不会技术，怎么办？

**A**: **工具必须傻瓜式**：
- ✅ 界面简洁，按钮明确（"开始测试"、"提交"、"保存访谈"）
- ✅ 不需要登录，输入姓名即可使用
- ✅ 提供简单的使用说明（1页A4纸）
- ✅ 开发者和学生一起测试1次，他们就会了

**建议**：开发完成后，找1-2个学生提前试用，收集反馈再优化。

---

### Q6: 访谈记录可以录音吗？必须打字吗？

**A**: **两种方式都可以**：

**方案A（打字）**：
- ✅ 简单，不需要语音识别
- ❌ 访谈者负担重，可能遗漏内容

**方案B（录音+摘要）**：
- ✅ 访谈过程录音，访谈者事后整理摘要
- ✅ 访谈时更专注对话
- ❌ 需要额外时间整理

**建议**：10天MVP先实现"打字记录"（P0），如果时间允许，可以加"上传音频文件"功能（P1）。

---

### Q7: 必须按照6个阶段顺序访谈吗？

**A**: **不是必须，但建议按顺序**：
- ✅ 6个阶段有叙事逻辑（认识→使用→信任→相处→理解→重新定义）
- ✅ 按顺序访谈，受访者更容易进入反思状态
- ✅ 但可以根据受访者兴趣调整（如他对"隐私"特别关注，可以深入Q11）

**工具应该支持**：
- ✅ 默认显示6阶段顺序
- ✅ 允许访谈者点击任意阶段/题目进行追问
- ✅ 灵活性 > 严格性

## 🎯 八、最终验收标准

### 功能验收

**必须能完成以下流程**（不能fail）：
1. 社会学学生打开工具 → 输入姓名 → 进入"开始测试"
2. 受访者完成15题测试（7点Likert）
3. 工具生成类型描述 + "符合你的感觉吗？" + 文本框
4. 受访者简单反馈后，进入访谈界面
5. 访谈者看到当前阶段（如"阶段2：使用AI"）+ 追问建议
6. 访谈者基于追问引导对话，记录受访者回复
7. 访谈完成，记录保存，可以导出

### 用户体验验收

**社会学学生必须能**（不能fail）：
- ✅ 独立完成整个流程（不需要开发者在场）
- ✅ 理解每个界面的用途（按钮清晰、流程合理）
- ✅ 快速找到需要的功能（不需要翻复杂菜单）
- ✅ 遇到问题时知道怎么解决（简单的帮助说明）

### 访谈效果验收

**访谈产出必须**（不能fail）：
- ✅ 包含受访者的15题答案
- ✅ 包含受访者对类型的反馈（认同/质疑/修正）
- ✅ 包含至少3个阶段的深度访谈记录
- ✅ 访谈记录能导出为Word/PDF，方便后期分析
