**文档版本**: v2.0（设计变更：保留概念总结页 + 之后追加尾声页）
**创建日期**: 2026-07-26
**优先级**: 🟠 P1（体验优化）
**预估工时**: 3-4小时
**前置依赖**: 无（可与v3.3其他任务并行）
**屎山治理级别**: 🟢 低风险（新增组件 + 对现有页最小化修改）

> 📌 **v2.0设计变更说明**：
> v1.0原计划是"替换"概念总结页（删除4个深问，新建尾声页）。
> v2.0经产品方反馈调整：**保留概念总结页**（4个深问作为质性访谈的"最后深度挖掘"有价值），**在其之后追加**尾声页（感谢+成就总结）。
> 核心变化：
> - 第一章：修改对象从"替换"变为"保留+追加"
> - 第二章：重构意图从"删除4问"变为"补足收尾仪式"
> - 第三章：流程从2步变为3步（概念总结页→状态A→状态B）
> - 第四章：屎山策略从"@deprecated标记"变为"最小化按钮修改"
> - 第五章：执行清单相应调整

## 📋 一、修改对象

### 1.1 当前状态

**当前页面名称**：概念总结页（访谈流程最后一页）

**当前页面位置**（推测）：
- 路由：`/interview/summary` 或 `/interview/conclusion`
- 组件文件：`InterviewSummary.jsx` / `InterviewConclusion.vue`（具体以实际项目为准）
- 入口：访谈流程第6阶段"重新定义AI"之后

**当前页面内容**：
- 标题："🔬 概念总结：AI素养是什么？"
- 4个结构化深问（一句话定义/补充维度/设计测试/标准批判）
- 每问附带"🎯目的"说明（暴露给采集端界面）
- 底部按钮："← 返回访谈" / "完成访谈并保存 →"

**当前页面的价值定位（v2.0调整）**：
4个结构化深问是质性访谈的"最后深度挖掘"环节——通过定义、补充、测试、批判四个角度，把访谈中浮现的认知再次激发。这是v1.0中被错误判断为"应该删除"的部分，v2.0确认保留。

### 1.2 修改后的目标状态

**概念总结页（保留）** → 追加两个新状态：

| 顺序 | 状态 | 名称 | 可见人 | 触发时机 |
|------|------|------|-------|---------|
| 第1步 | **概念总结页（保留）** | 4个深问 | 访谈者+被访者 | 访谈最后一步（原有逻辑） |
| 第2步 | **状态A：对话尾声页** | 感谢+旅程条 | 访谈者+被访者 | 概念总结页点击"继续尾声 →"后进入 |
| 第3步 | **状态B：访谈者收尾弹窗** | 成就可视化 | 仅访谈者 | 状态A点击"完成访谈并保存"后触发 |

**概念总结页的唯一修改点**：
- 底部右按钮文案：`完成访谈并保存 →` → `继续尾声 →`
- 其他内容（4问、目的栏、左按钮"返回访谈"）**全部不动**

## 🎯 二、修改目的

### 2.1 核心问题诊断（v2.0重新定位）

**原v1.0判断**：4问深问"主题重复+认知负荷错配+学术深度过重+目的栏外泄"，应该删除。

**v2.0修正判断**：4问本身有质性访谈的深度价值（是访谈中"概念再激发"的一环），不应该删除。真正缺失的是**4问之后的"收尾仪式"**——访谈结束时，访谈者对被访者缺少感谢、缺少成就可视化、缺少"画句号"的环节。

**修正后的问题清单**：

| 问题 | 严重度 | 说明 | 处理方式 |
|------|-------|------|---------|
| **缺少感谢收尾** | 🔴 高 | 4问结束后直接弹"保存"按钮，被访者没有得到温暖的句号 | ✅ 新增状态A（对话尾声页） |
| **访谈者无收尾仪式** | 🔴 高 | 保存后无任何"采集完成"的反馈，访谈者体验断层 | ✅ 新增状态B（访谈者弹窗） |
| **"目的栏外泄"** | 🟠 中 | "🎯目的：让受访者……"是脚本内部提示，暴露在采集端 | ⚠️ 建议后续迭代修复（不在本议程范围） |
| **主题重复（与Q15）** | 🟡 低 | 4问与Q15都在"定义AI"主题上，但4问是"深度再激发"而非简单重复 | 不处理（保留价值） |
| **认知负荷高** | 🟡 低 | 4问是学术深问，但访谈结尾的深度挖掘是质性方法的合理设计 | 不处理（保留价值） |

### 2.2 重构意图

**在概念总结页之后，追加一个完整的"收尾仪式"**——4问深度挖掘完成后，访谈者对被访者表达感谢+可视化旅程，访谈者对自己有一个采集成就的反馈。

具体实现两个追加：

1. **追加"对话尾声页"（状态A）**
   - 在概念总结页点击"继续尾声 →"后展示
   - 内容：感谢语+6站chip旅程条+收束句（活泼轻松）
   - 作用：给被访者一个温暖的句号

2. **追加"访谈者收尾弹窗"（状态B）**
   - 在状态A点击"完成访谈并保存"后触发
   - 内容：辛苦表达+4个可视化成就卡片（时长/题数/维度覆盖/编号）
   - 作用：给访谈者一个仪式感的收尾

### 2.3 设计哲学对齐

本次重构对齐v3.3设计升级文档的两个核心原则：

- **三种界面状态**：概念总结页是"访谈中态"的深度挖掘尾声，状态A是"访谈中→访谈后"的过渡，状态B是"访谈后态"的入口
- **从模块化到空间化**：不再让"保存"按钮突兀地结束4问，而是用一个聚焦的"收束态"完成过渡

```

    │  4个结构化深问（定义/补充/测试/批判）

    │  访谈者对被访者说感谢+成就总结

    │  底部右按钮："完成访谈并保存 →"

    ↓

    │  表达辛苦+可视化成就
    │  （仪式感）
    ↓ 访谈者选择
    ├── "查看访谈记录"
    ├── "开始下一场访谈"
    └── "返回首页"
```

**关键衔接点**：
- 概念总结页 → 状态A：概念总结页的右按钮文案改为"继续尾声 →"，点击后跳转到状态A
- 状态A → 状态B：状态A的右按钮"完成访谈并保存 →"触发保存，保存成功后弹窗

#### 3.3.5 弹窗数据结构

```typescript
interface CelebrationDialogData {
  // 标题区
  emoji: string;              // "🎉"
  title: string;              // "访谈采集完成！"
  subtitle: string;           // "辛苦了，刚刚完成了一场深度对话的采集。"

  // 成就卡片（动态计算）
  achievements: AchievementCard[];

  // 元信息
  date: string;               // "2026-07-26"
  interviewer_name: string;   // "管理员·lps"
}

interface AchievementCard {
  icon: string;       // "⏱️"
  value: string;      // "32 分钟"
  label: string;      // "访谈时长"
}

// 动态生成函数
function buildCelebrationData(session: InterviewSession): CelebrationDialogData {
  const durationMin = Math.round(
    (session.completed_at - session.started_at) / 60000
  );
  const answeredCount = session.answers.filter(a => a.value !== null).length;
  const stagesCovered = new Set(
    session.answers.filter(a => a.value !== null).map(a => a.journey_stage)
  ).size;

  return {
    emoji: "🎉",
    title: "访谈采集完成！",
    subtitle: "辛苦了，刚刚完成了一场深度对话的采集。",
    achievements: [
      { icon: "⏱️", value: `${durationMin} 分钟`, label: "访谈时长" },
      { icon: "📝", value: `${answeredCount} 题`, label: "完整回答" },
      { icon: "🗺️", value: `${stagesCovered} / 6`, label: "维度覆盖" },
      { icon: "🏷️", value: `#${session.respondent_code}`, label: "受访者编号" }
    ],
    date: formatDate(session.completed_at),
    interviewer_name: session.interviewer_name
  };
}
```

## 📐 七、设计意图总结（一页纸版）

> 以下是本议程的核心设计意图，供快速理解。

| 维度 | v1.0原计划 | v2.0最终方案 |
|------|----------|------------|
| **概念总结页** | 删除4问，标记deprecated | 保留4问（作为深度挖掘） |
| **修改范围** | 替换整个组件 | 只改1个按钮（文案+onClick） |
| **新增内容** | 2步（状态A+状态B） | 2步（状态A+状态B，不变） |
| **整体流程** | 2步（状态A→状态B） | 3步（概念总结页→状态A→状态B） |
| **屎山治理** | 全新建组件，旧DEPRECATED | 新建组件+最小化修改（按钮） |
| **保存逻辑位置** | 状态A的按钮 | 状态A的按钮（不变） |
| **"目的栏外泄"问题** | 通过删除4问解决 | 不在本议程处理（建议后续迭代） |

**一句话总结**：保留概念总结页的4个深问（作为质性访谈的最后深度挖掘），在其之后追加一个"对话尾声页"（感谢+旅程条）和"访谈者收尾弹窗"（成就可视化），给被访者一个温暖的句号，给访谈者一个仪式感的收尾。对概念总结页只做最小化修改（1个按钮），全部新增内容在独立组件中。

**设计决策的理由（v2.0变更记录）**：

1. **为什么保留4问**：产品方反馈，4问是质性访谈中"概念再激发"的环节，与Q15的"开放空间"是不同角度（Q15是个人使用原则，4问是社会化定义）。主题有重合但深度不同，不应删除。

2. **为什么把保存逻辑移到状态A**：概念总结页4问完成后，还需要一个"自然的句号"（感谢+总结），如果保存按钮还在概念总结页，被访者会在4问刚答完就被打断，缺少收尾仪式。

3. **为什么不处理"目的栏外泄"**：这是概念总结页内部的展示问题，与"收尾仪式"是两个独立问题。本议程聚焦收尾，目的栏问题留给后续迭代（避免一个议程承担过多职责，符合"少补丁、多深思"原则）。
