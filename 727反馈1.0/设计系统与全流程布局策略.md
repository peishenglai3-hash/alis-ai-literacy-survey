# 设计系统 + 全流程布局策略

**文档版本**: v1.0
**创建日期**: 2026-07-27
**定位**: 🔑 全引擎共享的视觉基准 + 各流程布局策略
**用途**: ① 开发者构建/重建任何界面时的目标基准 ② 后续各屏迁移到统一视觉语言的地图
**核心原则**: **视觉语言统一，布局模式因任务而异**

---

## 📐 零、核心原则（先读这一段）

"统一"有两个独立维度，必须分开：

| 维度 | 含义 | 要求 |
|---|---|---|
| **视觉语言** | 配色、字体、间距、卡片/按钮/chip 样式、图标、动效 | **全引擎强制统一** |
| **布局模式** | 竖向滚动 vs 空间化不滚动 | **因任务而异**，不强求一致 |

**关键认知**：访谈界面做成"不滚动的认知地图"，与其他"滚动的报告页"**不冲突**——只要它们用同一套视觉 token（同一套配色/字体/卡片），布局不同也像一家人。

> 不要为了让访谈屏"统一"而退化成滚动。统一的是视觉语言，不是布局模式。

**铁律**：访谈屏（实时对话）= 不滚动；报告类（阅读）= 该滚就滚。边界上的布局切换是合理的（暗示"换模式了"），只有**同一流程内**布局乱跳才是割裂。

---

## 🎨 一、视觉语言（Design Tokens）— 全引擎共享

> 以下是所有界面共用的 token。无论哪个屏、什么布局，都从这套 token 取值，**禁止各屏自定义颜色/字体/间距**。以下数值已与 `v3.3认知地图布局_可视化.html` 一致，可直接作为 CSS 变量落地。

### 1.1 配色（Color）

```css
:root{
  /* —— 背景 —— */
  --bg:        #efebe3;   /* 暖纸色底（长时间使用不刺眼） */
  --surface:   #ffffff;   /* 卡片/焦点区主表面 */
  --surface-2: #f6f3ec;   /* 次级表面（觉察带等"后退"区） */

  /* —— 分割线 —— */
  --line:      #e3ddd1;
  --line-soft: #ece7dc;

  /* —— 文字 —— */
  --ink:       #211f26;   /* 主文字（近黑暖墨） */
  --ink-2:     #4a4754;   /* 次级文字 */
  --muted:     #8d8896;   /* 辅助文字 */
  --faint:     #b4b0b9;   /* 占位/极弱 */

  /* —— 功能色（状态点缀，非大面积铺色）—— */
  --accent:     #6957c9;  /* 紫：当前/进行中/选中 */
  --accent-soft:#ece9f7;
  --done:       #3f9d77;  /* 绿：已完成 */
  --done-soft:  #e4f1ea;
  --ai:         #bd7a2e;  /* 琥珀：AI 生成内容（必须标注） */
  --ai-soft:    #f5ead7;
}
```

**配色用法纪律**：
- 主色是**暖中性**（bg + surface），功能色（紫/绿/琥珀）只做**状态点缀**，不大面积铺
- **禁止**紫白渐变铺底（既是设计纪律，也避免"AI 模板感"）
- AI 生成的任何内容（气泡、建议）**必须**用琥珀色标注，区分人工/机器

### 1.2 字体（Typography）

```css
--sans:  -apple-system, BlinkMacSystemFont, "PingFang SC", "Noto Sans SC", "Microsoft YaHei", system-ui, sans-serif;  /* 中文正文/UI */
--serif: "Instrument Serif", "Songti SC", Georgia, serif;   /* 展示性标题/编号 */
--mono:  "JetBrains Mono", ui-monospace, "SF Mono", monospace;  /* 数据：时间戳/分数/ID/标签 */
```

**三套字体的分工**（这是产品的"声音"）：
- `--sans`：中文正文、UI 控件
- `--serif`：大标题、题号、品牌字（赋予编辑/仪器质感）
- `--mono`：一切"数据"——时间戳、评分、编号、来源标签（强化"研究仪器"气质）

### 1.3 间距 / 圆角 / 阴影

```css
/* 间距：8px 节奏 */
space-1: 8px;  space-2: 16px;  space-3: 22~24px;  space-4: 30~34px;

/* 圆角 */
--r-card:  14px;   /* 卡片/大容器 */
--r-inner: 9px;    /* 内部元素（输入框、小卡片） */
--r-pill:  999px;  /* chip/tag */

/* 阴影 */
--shadow-card: 0 1px 2px rgba(33,31,38,.04), 0 18px 40px -22px rgba(33,31,38,.22);
--shadow-soft: 0 1px 2px rgba(33,31,38,.05);
```

### 1.4 核心组件（所有屏共用同一套）

| 组件 | 规范 |
|---|---|
| **卡片** | `--surface` 底、`--r-card` 圆角、`--shadow-card`、padding 随密度调 |
| **按钮-默认** | 白底、`--line` 边、`--ink-2` 字、hover 变 `--ink` |
| **按钮-主操作** | `--ink` 实底、白字（不用紫色实底，紫色只做状态点缀） |
| **输入框** | 白底、`--line` 边、`--r-inner`；占位符用 `--faint` |
| **chip/tag** | `--r-pill`、配 soft 色（如 `--accent-soft` + `--accent` 字） |
| **tab** | active = 白底 + `--line` 边 + `--shadow-soft`；inactive 透明 |
| **来源标签（气泡）** | preset=`--muted`/灰；cross=紫；ai=琥珀；manual=绿 |

## 🗺️ 二、全流程布局策略（每个屏该用什么布局）

### 2.1 三种"任务态"→ 布局模式

| 任务态 | 认知特征 | 布局模式 | 典型屏 |
|---|---|---|---|
| **实时对话** | 要一眼看全、不打断倾听、信息同屏共存 | **空间化（grid）、不滚动** | 访谈界面 |
| **阅读报告** | 信息量大、按顺序读、可回看 | **竖向滚动**（合理） | 结果页、访谈后回顾 |
| **尾声/过渡** | 仍在对话中、内容少、需仪式感 | **空间化、居中、不滚动** | 尾声页、收尾弹窗 |

### 2.2 各屏映射表

| 流程/屏 | 当前状态 | 目标布局 | 任务态 | 备注 |
|---|---|---|---|---|
| **访谈界面** | 左右两栏+滚动（坏） | 🎯 grid 三区、**不滚动** | 实时对话 | **试点，Phase 1 重建** |
| 概念总结页（4问） | 紫色卡片纵向堆叠+滚动 | 倾向空间化（4问可 2×2 或紧凑列表） | 尾声/过渡 | 仍在访谈流内，建议与访谈屏同语言；滚动可作过渡保留 |
| 尾声页（议程5） | 待建 | 居中、不滚动 | 尾声/过渡 | 感谢+旅程条，仪式感 |
| 访谈者收尾弹窗 | 待建 | modal（天然空间化） | 尾声/过渡 | 成就卡片 |
| 结果页 | 滚动报告 | **保留滚动**，套用新视觉 token | 阅读报告 | 布局不动，只换皮 |
| 访谈后回顾页 | 滚动 | **保留滚动**，套用新 token | 阅读报告 | 同上 |
| 访谈前准备页 | 滚动 | 简洁、可滚动，套用新 token | 准备/导航 | — |

> ⚠️ 你昨天发的 5 张"其他流程"截图，需逐张归入上表对应行（多数会落在"阅读报告→保留滚动+换皮"）。归类后即知哪些要改布局、哪些只换视觉 token。

### 2.3 为什么"访谈滚动 / 报告也滚动"≠ 必须统一

从"访谈"切到"结果"是**天然的上下文切换**（你在对话 → 你在读报告）。边界上换布局是**信号**（"模式变了"），不是割裂。真正要避免的是**同一流程内**布局乱跳——比如访谈界面内部有的题滚动、有的题不滚。

## 🚀 三、分阶段落地（不是推倒重做整个引擎）

| 阶段 | 做什么 | 成本 | 产出 |
|---|---|---|---|
| **Phase 0** | 把本文档的 token 落成项目的 `design-tokens.css`（或等效） | 小 | 全引擎共享变量 |
| **Phase 1（试点）** | 访谈界面在 token 上**重建**为认知地图（定点重写，不动旧组件） | 中 | 核心痛点解决 + 新视觉首个样本 |
| **Phase 2（增量）** | 其他屏**迁移到 token**——布局不动（该滚还滚），只换配色/字体/组件 | 视屏数 | 全引擎视觉统一 |

**Phase 2 优先级**：按"用户最常碰到的屏"排，结果页 > 回顾页 > 准备页。不必一刀切。

---

## 👨‍💻 四、给开发者的执行要点

1. **先建 `design-tokens.css`**（Phase 0），所有界面引用，禁止各屏写死颜色/字体
2. **访谈界面定点重写**（Phase 1）：新建干净组件用 token 实现认知地图，旧组件保留不删（按《开发核心指导》策略2 + v3.3 §12.2）
3. **其他屏暂不动布局**，Phase 2 只替换视觉 token
4. **任何 AI 生成内容用琥珀色 `--ai` 标注**
5. 验收硬门槛（访谈屏）：**1920×1080 视口下零纵向滚动、三区全可见**
